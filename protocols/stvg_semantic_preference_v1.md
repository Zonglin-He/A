# Semantic preference feedback: bounded interface feasibility before matched Student factorial

Question: can the same frozen R1 and Qwen provide object/role-discriminating
preference on a common visual support, and can it be converted to actual Student
parameter benefit? Teacher replacement alone is not a mechanism contribution.
RLCF already uses frozen CLIP feedback for test-time reinforcement learning:
https://arxiv.org/abs/2305.18010. No claim of literature priority here.
Qwen9B uses 8*(3 DeltaNet +1 gated attention) blocks, per its official model card:
https://huggingface.co/Qwen/Qwen3.5-9B. No old all-layer LocalizationHeads port.

Order: finish and publish current Qwen Direct32 versus revised R1 Direct32 first.
Then actual preference interface qualification only: eight fixed parents (first4
per domain of the same exposed32), slot0 only, two frozen Teachers, original4
context pixels and one candidate-labelled anchor, ordinary and reverse label
orders. At most32 real prefill forward calls, zero free generations, zero Student
fits, zero new Temporal/DINO/backbone/download/GT reads. Two hours after dependency
admission; download/dependency wait at most original24h, no deadline renewal.
Negative task results do not select a Teacher or Source subset.

Candidate support for all128 anchors is prepared before any new preference:
reuse the frozen weight-free E1 proposal tracks, original order (Source then
original candidate IDs), first four legal existing center boxes, no new ranking,
NMS, GT routing or geometry repair. At least two legal boxes needed to make a
choice; deficient pools retained explicitly, not substituted with DINO/GT boxes.
For each anchor the full original image is retained, only outlines/local IDs are
added; exact boxes, colours, render hashes and both permutations are bound.
This can miss the correct referent or contain only local variants: coverage must
be measured later, not inferred from the existence of four proposals.

Actual answer evidence: final next-token raw model log probabilities for exact
single-token labels 0..K at a fixed native assistant prefix. Check tokenizer IDs
are single, unique and decode exactly. 0 means explicit none/uncertainty. Report
raw allowed-label probability mass and full-vocabulary argmax, as well as the
posterior conditional on the restricted label vocabulary. It is a model preference,
not calibrated truth probability or verbal confidence. Restore each permutation
to candidate identity, report total variation/order sensitivity and average the
two restored distributions. Do not discard 0 or renormalize it out in reports.
Native R1/Qwen processors/clock/model/BF16/resource identities are checked;
repeat neither failed model requests nor alternate prompts based on output.
Engineering qualification requires finite correctly aligned evidence, not a
minimum number of selected targets or a GT success threshold. No target labels
are opened in this phase. Root must inspect actual rendered evidence.

The next matched Student design is a separate implementation lock after actual
interface readback. Fixed candidate logits z_i with detached pT under Gaussian
NLL are **fixed-support distillation**, not on-policy resampled Gaussian OPD.
The CPU contract implements exactly that gradient and stops gradients to actions
and Teacher weights; it does not claim an on-policy identity. Before any Student
launch root must bind candidate coverage, reference admission/rollback, covariance,
response-target conversion and same-support geometric control. Silently assigning
K region probabilities to 32 different newly sampled actions is forbidden.

Requested factorial: R1/geometric, R1/preference, Qwen/geometric,
Qwen/preference, same exposed32/candidates/observation/Student1792/update budget
and final temporal evaluation. Original Direct32 rows are portability references;
they are NOT the same-support geometric control for this factorial. A fixed-support
geometric control must be rerun under the same support before crediting the
feedback change. Retain same-information parameter-free hard-region/D2 controls,
all no-fit/negative/unknown parents, same-time and unobserved-frame geometry,
paired intervals, real call/token/wall costs. No more than128 additional fits in
a later explicitly versioned finite lock; no fitting is dispatched by this
interface controller. Root continues that authorized task once the conversion
is concrete and reviewed; no new user permission needed within this scope.

Role-swapped queries can be a separately locked consistency panel; they are not
automatically false examples, causal labels or a basis for GT-free online routing.
No automatic query paraphrase search. Semantic identity labels require actual
pixel review with uncertainty; model assistance is labelled. Semantic512 remains
44 model-assisted/468 pending, not completed by this engineering qualification.
