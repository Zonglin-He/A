# Correction: historical expert interpolation was an E-tail hybrid

2026-11-03 code and cached-array review identified a baseline-definition issue. `stvg/paper_panel.py::interpolation` starts from shared-corrected E, then overwrites the span between valid expert observations with center/log-size interpolation. Outside that span it retains E. Accordingly, prior matched-time full-domain differences HC +2.134753pp / Vid -0.106955pp concern **expert interpolation with E outside anchor coverage**, not pure expert interpolation. Earlier abbreviated descriptions as pure interpolation were inaccurate. The scores themselves are preserved as results of the actual historical hybrid.

Both domains used the same function. Unequal full query counts alone were not a within-query fairness violation, since methods were paired on identical queries/intervals within each domain. However, the hybrid had an added method-dependent E input. In the unchanged fixed128 panel, that tail enters the common predicted event for32HC queries and35Vid queries. No labels or model calls were used to establish these input dependencies.

At the user's request an independent [pure-expert128 correction](../pure_expert_interpolation_v1/ANALYSIS.md) now uses only original eight expert boxes and physical observation/frame times. Between anchors: the same linear-center/log-size convention. Before the first and after the last anchor: hold the nearest endpoint expert box. Anchors are restored exactly. No Source/E boxes, features, temporal update, DP, additional expert or tracker enters the interpolation estimator.

The Table11-style spatial comparison retains the same existing Current interval for both strategies, so every query has identical tIoU. This common evaluation condition is not a temporal update inside the pure interpolator. No new GPU/Source/expert/model/optimizer/RGB decode; only256new official pure-baseline CPU checks, independent whole128 cold-array/input-SHA/means audits and complete signed/shortlong/cost reports.
