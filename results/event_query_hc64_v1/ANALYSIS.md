# HC64 事件反馈与真实时间query：结果与原因

本轮按用户要求暂停原论文全量，HC1902评分保留、Vid1373/10303完整输出保存；不自动恢复。
这是既有64父来源曝光开发实验，不是官方全量或独立确认。空间沿用完整框传播和固定DP，
仅随新时间区间正常选择路径；另保存NativeG6同一空间轨迹固定的纯时间分析。

## 本轮实际做了什么

旧HC128公开逐条结果回读：事件读出使45条时间改善、82条退步、1条持平；退步中63条
锚点事件AUC仍>.5。由此检验：不是再找token接口，而是区间评分与实际时间query学习。

HC64旧完整语义张量当前不可用，只补采同一ReferDINO同八帧，每条一次，64成功查询/512帧；
保留时间融合后pre-max token，按已归档词组/子词规则聚合，E整轨迹关联不逐帧换身份。
64条所选原生专家框全部逐位恢复。复用已有Source224实际decoder输入，无新Source编码器、
448、时间头训练或空间适应。模型全冻结，实际学习每query共享两offset的256维临时残差。

固定10步Adam(.01)，残差按原query RMS归一化，L2相对半径.1，重置optimizer，只读最后状态。
两种反馈各给Direct与Query完全相同的目标：Raw为原物理Voronoi内外均值差标准化后，以
q0×exp(score)保留原生后验；Predictive为八点曲线留一预测增益，正斜率ridge1、组内外至少
各2锚点，未知score0。单位系数预先固定，不扫描温度或按GT挑步数。
LegacyContrast另复现旧无原生后验保护的硬选择；NativeG6保留当前六层/双offset旧hull/MBR。

## 机制判断

1. **丢弃原生时间判断是已测的重要损伤。** 旧硬对比t38.8586%；保留q0后的RawDirect
   为55.3419%，接近但仍低于NativeG6。这个差同时包含连续支持、标准化、概率重加权与MBR，
   不能把16.48pp都唯一归于某一项。它说明旧硬选择失败不能当作token毫无信息。
2. **更稳定地预测同一教师响应，没有自动变成更正确的事件监督。** PredictiveDirect
   低于RawDirect，预测评分未建立额外收益。ReferDINO八点已共同时间融合，留一的是曲线
   回归拟合，不是从教师输入隐藏该帧，不能写成独立语义预测或严格防泄漏跨锚点验证。
3. **query真实学习，但不能把减损当成获得新纠错信息。** 两组63/64 loss下降；各17条
   tIoU退步时loss仍下降。Query相对Direct的t均值+.4007/+.7429pp，两个CI跨0；其后验
   TV仅.0402/.0368，目标TV为.1685/.2187，更多保留原生也能解释较小损伤。
4. **有限拟合与反馈问题同时存在。** KL平均只消除24.11%/13.13%；未有查询触发半径截断，
   因此本轮不能归为“半径卡住”，也不能断言256维表达能力不够。十步预算是否尚未收敛，
   与可达方向限制未被完全区分。教师期望固定空间v增量+.4656/+.4983pp，但95%CI均跨0；
   query期望增量约−.0122/−.0184pp且CI跨0，尚未证明稳定新增知识。
5. **八点支持仍存在具体边界歧义。** PredictiveDirect损伤的26条中20条，在与所选区间
   相同八点成员模式的候选里，仍存在比原生更好的区间。这只是离线容量，非可部署oracle。
   Predictive对这些区间的证据分数按构造相同，必须靠其他时间证据或原生先验区分；
   Raw的物理分数可在同模式内变化，因此不能把Raw同模式称严格分数相同。

- RC042：RawDirect把t85.94%改为24.88%，RawQuery仍85.94%。这里是保留原生而避免
  直接坏更新，不是query学到了超过原生的新边界。
- RC025：RawQuery的t30.54%→25.99%，完整v23.48%→19.63%，loss下降；拟合方向不等于正确。
- RC063：RawQuery的t63.44%→65.48%，完整v30.43%→31.41%，有实际局部正例，但整体未兑现。
- RC029：PredictiveQuery的t29.77%→21.16%，完整v20.45%→13.36%；留一曲线预测也会强化错误。

短/长仅离线分组：13短/51长。RawQuery相对Native t−.9061/−.0434pp；PredictiveQuery
为−.3017/−.4466pp，未形成长短都正。没有按GT时长选择参数或输出。

## 裁决
