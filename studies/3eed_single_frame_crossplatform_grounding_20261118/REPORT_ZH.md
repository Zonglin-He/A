# R159　单帧跨平台 3D 指代定位

第一版的默认输入是目标平台的一帧 LiDAR、同步 RGB、标定和英文描述。以 Waymo → Drone 为例，加载 Waymo 的 epoch100 以及同源的融合与语言匹配权重，由 Drone 当前观测独立生成 256 个候选。R158 在完整描述条件下选中一个原始候选，随后用该帧激光点估计其水平朝向。输出是原始目标 LiDAR 坐标系中的 `[x,y,z,l,w,h,yaw]`，本次新增训练和测试时参数更新次数都是零。[运行说明](RUN_ZH.md) · [单帧代码](own_code/crossplatform/ground_single_frame.py) · [注册协议](experiment/PROTOCOL.json)

## 单帧主结果

5,942 条普通方向记录对应 2,971 个描述条目、1,984 个点云内容组。每条记录的三个读出共用源权重、同一帧、同一次采样及同一组候选。方向内部按记录平均，再给六个方向相同权重。Acc@25 和 Acc@50 使用三维有向 IoU 严格大于 0.25 和 0.50 的比例，表中单位为百分数。[总体结果](results/overall.csv) · [分方向三项指标](results/directions.csv)

## 与第二帧的关系

在之前用于选择规则的 1,798 条开发记录上，强制全体只用 A，三个单帧读出的 mIoU 依次为 **13.3945%、15.5988%、15.9997%**。同批记录允许有 B 时使用 B，R158＋PCA 得到历史混合协议的 **16.3212%**。两个普通数据范围的场景构成和权重不同，不能用 16.3212% 与主表的 12.9710% 作配对对比。

只有 764 条具备已配准的另一帧。在这 764 条上固定 R158 和 PCA，单帧 A 为 **15.8682%**，A＋B 为 **16.7724%**，配对增量 **+0.9041 个百分点**。92 条改善、85 条恶化、587 条持平。另一帧来自目标端可以配准的观测。方向内沿用开发清单原采样权重，在该子集内重新归一化。[配对结果](results/paired_changes.csv) · [历史开发集逐例记录](https://github.com/Zonglin-He/A/tree/da7522dfb5bd9f70194c8e69b5a4b031e0641d09/studies/3eed_language_candidate_overlap_readout_20261118/results/all_rows)

## 这次实际验证了什么

六个方向共做了 14 组真实原始输入回放，包含两个不同源模型向 Waymo 迁移时的五种相机视角。新入口只接收传感器文件、仅含相机字段的 JSON 与描述，从头解析文本。14 组的 256 个候选框、旧赢家、R158 赢家以及选中框的 PCA 结果均复现封存输出。所有候选的冻结概率最大绝对误差小于 10⁻¹⁵。裸命令行还在另一工作目录用相对路径完成 Waymo → Drone，返回单行 JSON 和正确的物理坐标。另作了新英文描述、重复输入、默认采样种子的工程验证。[原始输入复核](RAW_REPLAY.json) · [命令行复核](CLI_REPLAY.json) · [CPU 指标复核](AUDIT.json)

首张主结果表的 5,942 条记录使用 R158 当时封存的逐条采样种子。跨采集序列表的 3,072 条方向记录使用部署入口默认种子 0，并在本轮重新从原始传感器运行。R158 的规则选择参考了目标开发结果。附加集与选择集的原始点云和图像内容已隔开，但附加集的 81 个目标场景均在开发清单里出现过，FINAL 此次访问次数为零。这 5,942 条度量同场景中的其他内容，跨采集序列证据单列于上表。[评价范围](results/scope.json) · [3EED 原论文的跨平台设置](https://arxiv.org/html/2511.01755v1)
