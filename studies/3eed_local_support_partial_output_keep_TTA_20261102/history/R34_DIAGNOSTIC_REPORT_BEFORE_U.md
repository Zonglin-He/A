# R34 诊断阶段：更换检索 key 有开发收益，历史集合未显示一致改进

状态：528 条 A/DEV/R/S/T 的固定读出预测、CPU 算术审计、离线评分和独立审计已完成。**本报告不含 U128 新确认，不作最终采用决定；FINAL384 未读取。** 后续 U 的封存与评分应单独追加结果，不能用其标签选择 key、k 或更新范围。

本轮保持原 Waymo-only 初始化、R30 b1 query 匹配状态和22条反馈不变，只把控制修正传播范围的检索 key 从 source noun×query64 换成归一化 source h288。开发集平均 mIoU 从原 noun 门的24.5046提高到25.3794，但 R/S/T 表现不一致。因此，当前证据支持该替换值得按预定协议检验，尚不支持“已经稳定解决负迁移”。

## 唯一改动及同信息对照

h288 来自 source 最终 decoder query 进入匹配投影之前的隐表示，已经以点云和文字为条件。它没有增加 RGB、标签或外部模型信息；不是重新训练的状态，也不是 GRACE 的复现。先前无标签诊断显示它比64维 noun×query 的近邻间隔更大，这只构成接口选择的机制依据，不能代替任务效果。

两种 key 都先在每个 A 观测的256个 query 中找到最近候选，再排序不同 A 行；保留原 GPU float32 max/topk4，固定取第一个 A 行。支持标记仅来自原接受偏好的 P/N query，不把整条反馈行或未知第三实例当成支持端点。实际 A 推理不排除自身；前置 key 诊断排除自身仅用于观察区分度，二者用途不同。

对当前观测始终固定 source q0，以 `ell_eps(p)=log(p+1e-6)-log(1+1e-6-p)` 构造相对分数。此坐标用于有限精度推理，不替代 R30 训练的 exact log-odds。二值门 g 在0处返回 source、在1处返回 R30 端点，显式保持原 float32 饱和并列顺序。

同信息不更新对照是原22条偏好在 A 上生成的最小 group-level L2、margin0.1 QP 修正，按同 key、同门传递；每组只有一个目标项，不因重复 query 变大而提高权重。修正先从 A 检索，再相对当前观测 q0 锚定。另有同门平均覆盖和实际修正范数匹配的全局缩步对照。所有候选框冻结，没有新增优化器步骤、G调用或伪标签。

T128的 h 门改动仅发生在Drone：2条IoU改善、3条恶化，另有换query但IoU未变；Quad没有任务结果变化。原noun门在Drone是2条改善、1条恶化。该差异不能由h的数值间隔更大直接解释为更正确的传播。

平均候选门覆盖率也较低：DEV Drone/Quad为0.9521%/0.8179%，T为1.8555%/0.2869%。原noun门对应DEV2.4780%/1.3428%、T2.7222%/0.3357%。这是256个候选坐标上的覆盖比例，不是有效纠错样本比例。更低覆盖可以同时减少损害和丢掉收益，不能把大部分观测未改变称为已学会适应。

全部528条10臂任务值、平台指标、场景表及599条负比较均已保留，没有依据负例身份或IoU重新筛反馈。样本数量不等于独立场景数量；T的Drone只有一个场景，不能估计跨Drone场景泛化，也不将退化的场景重采样区间作为显著性证据。

## 接受反馈是否仍被执行

独立使用保存的最终完整分数检查全部22条偏好的方向与最终选中正组。原R30、h门R30、noun门R30、两种同门QP都满足6/6条要求换目标的B方向及6/6最终正组，通过原至少5/6方向、4/6最终正组的可行性规则。四个全局缩步对照均为0/6、0/6；其恢复frozen不能当成在保留纠错前提下的保护效果。

这项检查只说明已有偏好得到执行。偏好可能错误或只支持局部比较，不能把6/6落实等同于6条GT正确标签，也不能推导未知第三候选为负。全部220条“10臂×22偏好”执行记录保留在独立审计目录。
