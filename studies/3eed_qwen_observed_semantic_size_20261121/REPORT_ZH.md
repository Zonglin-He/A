# 实测粗几何经由类别和子类型，能否改善完整框补全？

**保留作为部署基准的 `C_E_Qsize`。** 在同一批 416 个普通物理帧上，实测粗几何只改变了 3/320 个有效选区的子类型，最终只改变 1 个成框。显式语义链 GS 与无粗几何的 S 有完全相同的 Acc@50 成功帧，均为 **24.86%**。GS 相对原框的 28.68% 下降 **3.82 个百分点**，救回 6 帧、误改 19 帧。[全量指标](results/metrics.csv) · [逐帧数据](results/rows.csv)

## 接入方式与实例控制

H 逐值使用封存的 `C_E_Qsize` 输出。S、GS、GD 共用原始四尺度节点、原 PCA 朝向、原窗口及 `complete()` 的锚定规则。先用原采样种子和节点 ID 恢复原选区及地形估计，再用原尺寸先验回放全部 320 个有选区的框，坐标差为 0。给 Qwen 的公制数据来自选区点本身。水平两轴使用当前 PCA 方向，竖直跨度使用实测 z 的最大值减最小值。320 个选区里有 319 个的原观测框包含向地面延长的高度，实际供模型使用的高度排除了这段延伸。[输入封存](results/input_seal.json) · [观测框重建](prepare.py)

| 方法 | 第一阶段 | 尺寸阶段 |
|---|---|---|
| H | 原模型封存结果 | 原尺寸，直接复用原成框 |
| S | 同一裁剪和指代表达 → 类别／子类型 | 同一裁剪和指代表达＋两个语义字段 → 完整长宽高 |
| GS | 同一裁剪和指代表达＋实测跨度及比例 → 类别／子类型 | 与 S 相同，使用全新上下文 |
| GD | — | 同一裁剪和指代表达＋实测跨度及比例 → 完整长宽高 |

GS 的尺寸阶段只收到新上下文中的两个语义字段。S、GS 标签相同时共享同一个尺寸结果。所有有效新尺寸交给原函数 `regions.complete(B_obs, dimensions)`。它根据原物理轴匹配长宽，保留观测范围下界，并随尺寸变化重算中心位置。首批回答中 Qwen 有时把已登记子类型放进类别字段。评分前按固定词表归位，子类型冲突时保留粗类别。这项结构修复覆盖 S 的 77 条和 GS 的 64 条回答，总共仅补做 64 次缺失的尺寸查询。原始回答与提示哈希保留，四组只使用一套最终评分。修复后，三个新方法各有 320 个有效新尺寸，96 帧沿用原回退，其中 5 帧原本缺框并计零。[主协议](PROTOCOL.json) · [分类字段归位规则](AMENDMENT.json) · [新尺寸接入](complete_predictions.py) · [预测封存](results/prediction_seal.json)

P³-VLM 验证了 3D 框的几何可以携带分类信息。本轮的处理信号来自部分实测回波，并按三维定位任务衡量最终结果。没有细粒度子类型真值，表中的改变记录反映模型输出变化。[P³-VLM 原文](https://p3vlm.insait.ai/static/p3vlm.pdf)

GS 对 H 的 Acc@50 差值为 −3.8194 个百分点，按平台内录制分组重抽样的 95% 区间为 [−6.77, −0.35]。在 224 个与原始开发集录制分离的普通帧上，H 为 27.4306%，S 和 GS 均为 25.1736%，GD 为 22.5694%。GS 对 H 救回 5 帧、误改 12 帧。整批普通样本此前已用于开发，录制子集报告沿用原分组。[按范围结果](results/metrics.csv) · [录制重抽样](results/evaluation_receipt.json)

**GS 对 S** 的 Acc@50 救回和误改均为 0。Acc@25 增加 0.2083 个百分点，mIoU 增加 0.0093 个百分点，两项都来自同一个 Quad 帧。**GS 对 GD** 的 Acc@50 高 3.5417 个百分点，救回 17、误改 2。S 对 GD 有同样的 Acc@50 配对结果。这两组尺寸读出的差异没有显示来自几何改变语义的增量。[配对结果](results/paired.csv) · [语义到几何的变化计数](results/semantic_funnel.csv)

## 三个实际改变语义的样本

320 个选区中 317 帧的类别和子类型均相同并复用尺寸。变化的 3 帧都在 Quad，粗类别均保持原值。长、宽、高用米表示。下表 IoU 采用全精度结果后显示为四位小数。[逐帧尺寸与中心变化](results/rows.csv)

| 匿名帧前缀 | S → GS 子类型 | S 尺寸先验 → GS 尺寸先验 | 成框变化 | IoU S → GS |
|---|---|---|---|---:|
| d895502e | 行人粗类 → 成人 | (1.2, 0.6, 1.8) → (1.2, 0.6, 1.8) | 位置及尺寸逐值相同 | 0 → 0 |
| 79c893b3 | 乘用车 → 车辆粗类 | (3.5, 1.7, 1.5) → (2.5, 1.7, 1.5) | 两种长度先验都低于实测长轴 3.855 m，实际尺寸与中心相同 | 0.6313 → 0.6313 |
| 6be5b238 | 乘用车 → 车辆粗类 | (3.5, 1.7, 1.5) → (2.5, 1.8, 1.5) | 长度减 1.0 m、宽度增 0.1 m，按原锚定中心移 0.502 m | 0.2117 → 0.2562 |

GD 把完整尺寸读成部分跨度的情况可直接追溯。320 个有效结果中有 120 帧，GD 返回的三个数与输入提示中四舍五入到两位小数的三个实测跨度完全相同，允许顺序不同。这 120 帧相对 H 误改 14 帧、救回 0 帧。例如 `79c893b3` 的三项实测跨度约为 3.85、0.38、1.23 米，GD 给出了 3.85、1.23、0.38 米，最终 IoU 从 H 的 0.7014 降到 0.4492。这种数值复用解释了 GD 一部分误改时的尺寸读出。[输入跨度、三组尺寸和逐帧 IoU](results/rows.csv)

## 运行及复核

使用同一个冻结的 Qwen3-VL-4B-Instruct，模型版本 `ebb281ec70b05090aa6165b016eac8ec08e71b17`。共 1,283 次真实调用，包括 640 次语义、320 次 GD、323 次独立语义条件尺寸。评分前完成全量预测封存。两个有向 IoU 实现最大差 6.66 × 10⁻¹⁶，冻结 H 的每帧分数与旧版逐值相同。独立重算所有尺寸和中心时，最大坐标差 7.11 × 10⁻¹⁵ 米。FINAL 未访问。[模型封存](results/model_seal.json) · [字段归位后新增尺寸封存](results/normalized_seal.json) · [独立复核](results/verification.json)

带本地前序缓存和模型时，运行顺序为 `prepare.py`、`run_qwen.py MODEL_DIR`、`normalize_and_read.py MODEL_DIR`、`complete_predictions.py`、`score_size.py`、`verify.py --private`。公开结果可直接用 `python verify.py` 重新计算配对和平台统计。全部匿名结果、回退和负例均保留。
