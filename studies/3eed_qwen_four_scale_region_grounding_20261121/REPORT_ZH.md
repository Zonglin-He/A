# Qwen 视觉选区与四尺度物理框补全

**最大的增益来自在选中的物理区域上补全整个框。** 在原 Qwen 面板的 96 帧上，保持 Qwen 独立二维定位、用四尺度选区并以 Qwen 尺寸和区域 PCA 方向锚定可见面，得到 **59.38% / 32.29% / 34.51%** 的 Acc@25 / Acc@50 / mIoU。相对原窗口中位深度，三项分别提高 **12.50 / 14.58 / 9.03 个百分点**。只替换中位数的回波集合时，Acc@50 仍为 17.71%。区域选点和整框补全在这批数据上提供了不同层次的作用。[初始对照](results/metrics.csv) · [不使用名词或关系的补全对照](results/controls_metrics.csv)

## 全部主要方法

Waymo、Drone、Quad 各 32 帧。冻结 Qwen 的 192 条原回答全部复用。A、C、F 和不使用名词的补全每物理帧出一次框。B 和 D/E 的语义条件版本使用两个迁入源模型，每平台 64 个方向记录。总体按三平台等权，原始方法和新读出统一使用严格有向 IoU 大于 0.25、0.50。[封存方案](PROTOCOL.json) · [D/E 消融方案](FOLLOWUP.json) · [补全对照方案](CONTROL_PLAN.json)

| --- | ---: | ---: | ---: |

| B · 同帧正式 v3，原评测文本格式 | 35.42% | 21.88% | 21.41% |
| C · 视觉选区，严格触发、全体回退 | 47.92% | 17.71% | 25.55% |

## 为什么提高了精确定位

**区域能过滤混杂回波，单靠一维中位深度的收益有限。** C 在 76 帧启用，余下包括 2 条无有效原生三维答案、9 条原拟合格少于 5 和 9 条没有区域提供 5 个中央拟合格。原中位数选到的回波与 C 选点结果在这 76 帧的真框归属均值为 **76.84% → 85.05%**。同点数错配为 76.75%。C 相对 A 在 Acc@25 救回 5 帧、误改 0 帧，Acc@50 救回和误改都为 0，mIoU 提高 1.14 pp。在 21 帧原窗口回波不足半数属于真框、但拟合格足够的例子中，最多只有 5 帧具备半数以上回波落入真框的候选，C 实际选对其中 4 帧。事后逐个比较 C 允许的全部节点，固定 Qwen 视线和框形时，理想选择也只比 A 多 4 个 Acc@50 达标帧，Quad 无新增达标候选。[回波与中心误差](results/geometry.csv) · [独立复算与事后上限](results/recount.json)

删除拟合之外的相机可见点后重新建树，Acc@25/50 仍为 52.08% / 17.71%，mIoU 为 26.66%。在 6,405 条属于标注目标且两个框都击中的留出射线上，首面深度 MAE 从 **0.378 降至 0.327 米**。同点数错配为 0.382 米。对全窗共同击中的 7,674 条射线评分，MAE 从 0.955 升到 1.052 米，表明选中的框主要贴合目标表面，原窗口中的其他表面仍可造成误差。经原始点索引核验，拟合树未保留任何原始留出格内的样本，有一个贴近格边界的拟合点因浮点投影差异被排除。[独立留出核验](results/split_audit.json) · [逐帧射线统计](results/surface.csv)

**D 的名词与关系对本批没有净增量。** 名词与提名证据改变了 34/192 个选区，最终 IoU 有 11 条变差、0 条变好，mIoU 相对 C 下降 0.32 pp。原 v3 关系项只在 8 条方向记录上可用，覆盖 4 个物理帧。开启后与 D 主体读出的选区和输出均一致。样本规模支持本批的组件判断，独立关系推理价值仍未验证。[D/E 触发与配对](results/followup_score_receipt.json) · [各方向结果](results/followup_paired.csv)

**固定区域后，整框的可见面锚定带来最大的 Acc@50 改变。** 相对 D 的同区域中位深度输出，Qwen 尺寸加区域 PCA 把 Acc@50 提高 13.54 pp，方向配对救回 36、误改 10。中位 3D 中心距离由 0.574 降至 0.481 米，尺寸平均相对误差的中位数约 10.4% 和 10.7%。因此，在这两种具体读出中，中心重估是明确变化。直接保留 C 的选区、移除 D 后，Qwen 尺寸加区域 PCA 还有进一步提升，Acc@50 从 A 的 17/96 到 **31/96**，救回 19、误改 5。按录制配对重抽样的增量区间为 [+5.02, +24.11] pp，受当前录制覆盖限制。最大单例改善 IoU 0.263→0.828，最重损伤 0.707→0.287，均保留。[中心、尺寸与长轴误差](results/followup_geometry.csv) · [全部补全配对及区间](results/controls_score_receipt.json)

| 只用拟合点的同补全读出 | Acc@25 | Acc@50 | mIoU |
| --- | ---: | ---: | ---: |
| 全部原窗口拟合点 | 22.92% | 12.50% | 16.52% |
| C 区域对应的拟合点 | 45.83% | 20.83% | 25.88% |
| 同窗同点数错配拟合点 | 22.92% | 12.50% | 16.48% |

三组在同一 75 帧使用相同的区域 PCA、底面处理和 Qwen 尺寸补全，其余均精确回退 A。正确区域比同点数错配多 8 个净 Acc@50 达标，mIoU 高 9.40 pp。只用中央匹配拟合点的完整精度低于用全选中区域的版本，这两项实验分别检验回波归属和区域完整几何的作用。[匹配补全对照](results/controls_metrics.csv) · [全体配对](results/controls_paired.csv)

## v3 重放与复现入口

上一份 Qwen 报告的 `registered` 已读取 v3 发布表的 `separate_direct` 列。本轮直接运行 v3，首次用原 Qwen 字符串输入，92 条回退记录的 IoU 与历史表不同。重放钩子将差异定位到地面高度修正前的冻结候选框。随后只换为 3EED 普通评测使用的描述格式，重新跑 192 条，全部 IoU 复现，最大差为 4.44×10⁻¹⁶。两次的原区域触发记录都为 8 条。所有 Qwen 答案沿用原先封存文件。[两种文本格式实跑](results/v3_text_replay_audit.json) · [回退追踪](results/v3_fallback_audit.json) · [正式 v3 固定实现](https://github.com/Zonglin-He/A/blob/eede68539fc8752832d854b8482076fc23d81957/v1/crossplatform/ground_regions.py)

C 在原 16,384 点抽样上调用官方地面估计和四尺度区域函数。原始可见回波在 4×4 像素格内取最近者，每个区域的可见格以最近采样点的归属和该尺度连接半径确定。以区域落窗比例乘区域解释窗口的比例选一个区域。在 C 的中位数对照中中央拟合格、相机射线、前表面到中心偏移、9D 姿态和尺寸均沿用 A，仅把中央拟合格缩成该区域的子集。E 的 Qwen 姿态先按官方 9D 约定通过标定转换成 LiDAR 直立 7D 框，再用它的水平长轴重新测量所选区域。补全以已测尺寸为下限，扩大到 Qwen 或区域预测的尺寸，并锚定面向观测者的水平面和底面。[Qwen 原始研究](https://github.com/Zonglin-He/A/blob/9c0bf6066e1695fc5b244a08c760ee46005bb0de/studies/3eed_frozen_qwen_metric_grounding_20261120/REPORT_ZH.md) · [官方 Qwen 3D 示例](https://github.com/QwenLM/Qwen3-VL/blob/284163291a9483a772675ace416206e6a8fbced5/cookbooks/3d_grounding.ipynb)

在公开目录运行 `python recount.py` 即可复算主指标、所有 C 配对计数、候选深度上限和 D/E 控制的一致性。完整复跑使用原环境和封存数据，依次运行 `region_depth.py`、`replay_v3.py`、`score_region.py`、`replay_registered.py`、`followup.py`、`score_followup.py` 以及 `controls.py predict` 和 `controls.py score`。B 原句实跑约 35 秒，D/E 冻结模型实跑约 80 秒，C 区域与深度重放约 3 秒。最终方案筛选使用本批结果作研发证据。保留 **Qwen 选区＋区域完整点支持＋Qwen 尺寸补全** 为精确定位的候选配置，主方法采用判断需要冻结后在未用来选型的录制上复核。[复算](results/recount.json) · [D/E 推理封存](results/followup_prediction_seal.json) · [最终补全封存](results/controls_prediction_seal.json)
