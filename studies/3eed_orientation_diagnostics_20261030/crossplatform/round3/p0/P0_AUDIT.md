# P0: source-only baseline and training feasibility audit

Status: no official Waymo-only checkpoint was found; source-only training was cancelled on the latest user instruction. Formal training completed 0 epochs and no source-only checkpoint exists. No target numerical ground-truth scoring was performed in this P0 audit.

## Acquisition evidence

The current official GitHub tree (843a901f5367a6be5cc484b97c6ecad462961dfa), release/tag/branch surfaces, project page, and HF file list were checked. The current HF baseline archive matches the already downloaded archive SHA256. Its complete ZIP central directory has 36,719 members and only one checkpoint, `final_6384/ckpt_6384.pth`. The collaborator's [issue 6 reply](https://github.com/worldbench/3EED/issues/6#issuecomment-4273059426) says other checkpoints were lost after a server reset. The project page links the same repositories. No other official source-only weight was found on these checked surfaces. This is an availability audit, not proof that no private checkpoint exists.

Only configuration/log text was extracted with safe-path checks. No new model or dataset archive was downloaded. An isolated committed code clone and existing compiled compatibility operators were prepared inside P0; old projects and the shared environment were unchanged. Full ZIP directory and extracted logs remain private evidence, not a public export.

## Source training recipe and actual loader

The official Waymo train script uses batch 24, 100 epochs, AdamW learning rates 1e-4/1e-3 (nonbackbone/backbone), weight decay 5e-4, clipping 0.1, six decoder layers, soft-token and contrastive supervision, self-attention, intermediate detection and joint detection. The default visual initializer is random; the optional PointNet checkpoint load is not active. RoBERTa-base is pretrained and frozen, while its training-mode dropout is retained. Initializing from the released mixed model and finetuning Waymo would not be source-only training.

The official loader actually constructs 3,682 Waymo training expressions and 3,782 source validation expressions, with 94 and 93 available scenes respectively and no scene overlap. Some official split-listed directories are absent from the dataset. At batch 24 and drop-last, this is 153 optimizer steps per epoch, 15,300 over 100 epochs. Eight deterministic CPU item checks verified finite 16,384-by-3 point tensors, positive source box sizes and nonempty source token maps. The single-object path returns XYZ despite `use_color`; defined geometric augmentation is not called. Sampling is stochastic and uses replacement for short point sets.

Scheduler execution differs from the apparent script values: `warmup_epoch=-1` is subtracted from milestones and MultiStepLR advances per optimizer step, so nominal epochs 25/26 yield effective offsets 26/27. This must be recorded, not silently corrected. The loss expects a real initialized distributed process group even at rank one. The first timing attempt failed on this prerequisite; its original log is retained. A retry initialized actual NCCL rank one without changing normalization, but was cancelled before any completed-step record. No valid training throughput or batch-24 full backward memory measurement was obtained.

## Time and cancellation

The only available reference is the official mixed-platform log: median 293.18 seconds per epoch at 530 batches, scaled to 15,300 Waymo steps gives 8,463.5 seconds, or about 2.35 hours of training. This is not a measured 5090 estimate. Original hardware and distributed setup are not established by that log, and validation, startup and checkpoint I/O add overhead. The user asked to avoid training if it was too long, and the parent directed immediate termination. The timing process and its four loader workers were stopped; only the unrelated existing ToDesk GPU process remained. No automatic full-training controller was created. `CANCELLED.json` is the authorization stop receipt, and the timing entry point now refuses to run while it exists. No further GPU repair/retry is authorized.

## Evaluation protocol and comparison to round 2

The released head predicts center and full dimensions only (6D), not yaw. Official single-platform validation selects query scores using a positive token map derived from the ground-truth target class and its caption synonyms. It therefore has target-class/span assistance. Round 2 used a modified text-only first-noun readout; its scores cannot be called identical official readout replication. Both conditions must be named explicitly when eventually evaluating a valid source-only model. The official evaluator also clamps sizes to at least 1e-6; raw invalid-size counts must be retained.

A future reauthorized source-only evaluation would use Waymo train and Waymo val only for model construction/selection, choose fixed epoch100 as primary, seal any source validation predictions every10 epochs, and score in a separate CPU process. Target Drone/Quad validation must never choose a checkpoint. On target evaluation, target numeric boxes must be excluded from adaptation inputs; the official class-assisted readout and a fixed text-only auxiliary readout must be reported separately. The numeric evaluator should use the official first seven GT fields, float64 yaw-only OBB geometry, sealed predictions and an independent implementation audit. The extra raw dataset fields must not be interpreted as pitch/roll.

The executable scientific source-only experiment remains incomplete because there is no eligible weight and training was cancelled. P1-P3 may diagnose the existing mixed model, but such results do not establish source-only cross-platform transfer. There are no P0 target performance numbers to report.
