# R33：在相同反馈与保持预算下，更换文字匹配接口没有获得开发集收益

运行状态：完成；封存预测的独立 CPU 测量：通过，执行范围限定见下文；方法裁决：本轮不采用文字投影接口，不扩大预算，不消耗 U128 新确认集。FINAL384 未使用。

本轮只回答一个问题：在原 R30 的 22 条外部偏好和输出保持约束下，把可更新接口从 query 匹配 MLP 换成 text 匹配 MLP，能否更好地执行反馈并提高总体开发指标？结果未支持这一替换。它不证明文字侧 TTA 普遍无效，也不重新证明 R30 对未见平台观测具有稳定收益。

## 固定设置及真实接口

共同初始化是同一 Waymo-only source。Drone、Quad 独立初始化和更新；候选框、decoder、backbone、cross-encoder、输入特征、反馈内容与读出不变。对 query/text 两个现有投影，各试学习率 1e-4、5e-4，AdamW、weight_decay=0、16 步、seed=0、beta=1，共 8 个平台状态、128 次优化更新，每个状态 184,960 个可更新参数。没有新增架构或 RGB 训练。

两接口结构均为 288→288→288→64，经过归一化参与 noun-token 匹配。`text_h` 是 cross-encoder 后已经结合点云的 text_memory；它并非纯文字嵌入。只更新末端 text 投影不会改变 decoder 的输入特征和候选框，也不会给学生增加缺失的 RGB 观察。query 特征本身同样已经读取完整文字，不能把本轮解释为“首次让学生使用关系”。

监督仍是原 group-max exact noun log-odds 的 softplus 排序损失，温度 0.1，Drone/Quad 原分母分别 10/12。原 19 个反馈观测贡献的全部 22 条偏好都保留，包括已知负例；没有使用 GT 黑名单。保持集合固定为原无反馈 A 观测 96/93，共 189；源第一名 q0 固定，约束相对 q0 的 log-odds 差。偏好和保持损失、平台隔离、A 的分组读出以及 DEV 的 raw argmax 均与旧 query 配置一致。

## 预登记选择结果

所有表内 mIoU 单位为 %，平均是平台等权平均。DEV64 是已暴露的旧开发集，每平台 32 条；它只承担预登记选择，不是独立确认集。可行性要求六条要求换目标的 B 反馈中至少 5 条方向成立、至少 4 条最终落入正组；每个平台使用同一接口和学习率。

| 配置 | Drone DEV | Quad DEV | 平台平均 | B 方向成立 | B 最终正组 | 可行 |
|---|---:|---:|---:|---:|---:|---|
| Frozen source | 20.6533 | 27.8834 | 24.2683 | — | — | 参照 |
| query MLP，1e-4 | 18.2351 | 30.0758 | 24.1555 | 3/6 | 3/6 | 否 |

| text MLP，5e-4 | 19.6045 | 27.8207 | 23.7126 | 3/6 | 3/6 | 否 |

预登记规则选择了原 query 5e-4。文字侧两个配置都没有通过可行性条件；即使取消该条件、只作机制诊断，最好的 text 5e-4 平均仍比 query 5e-4 低 **1.3783 pp**，比 frozen 低 **0.5558 pp**。query 1e-4 在 Quad 上更高，但 Drone 的下降使平台平均没有超过原 query；不根据单平台结果另选参数。

DEV 64 条中，query 5e-4 有 5 条 IoU 改善、5 条恶化；两种 text 配置各有 1 条改善、2 条恶化。其余包含 query 更换但 IoU 未变化的案例，因此“换了 query”不能当作纠错数。全部四配置、全部 1,088 个 A/DEV 逐例结果保留在 `results/ALL1088_TASK_ROWS.csv`，没有删除零值、退化或已知错误反馈。

## 拟合与传播诊断

较高学习率的 text 侧并非零更新：Drone/Quad 参数变化 L2 为 1.3349/1.0799；完成 16 次更新后，全部偏好分别满足 9/10、10/12，低于原 query 的 10/10、12/12。最终精确 log-odds 偏好损失分别为 1.55446/1.30319，原 query 为 0.05158/0.01304。这些是保存末态重新计算的值；fit trace 的 step16 损失记录发生在最后一次 optimizer.step 之前，两者不应混称同一个末态。

text 5e-4 对原 A208 平台平均 mIoU 相对 frozen 仍有约 +0.9372 pp，其中反馈观测确有局部改善；但 DEV 指标退化。text 1e-4 在反馈观测没有改变最终选择，同时其他观测仍可改变。这个结果说明，接口位置和局部拟合可以影响传播范围；它没有显示更好的总体开发迁移。A 参加了反馈拟合或保持损失，不能将 A 上的改善当成新观测验证。

不能从上述差异断言 text 接口容量不足或永久不可用：本轮只覆盖预登记两个学习率和 16 步，对称参数数目不代表两个接口的条件数或梯度尺度相同。现有证据支持“当前监督、保持约束和有限预算下，没有理由替换原接口”。本轮因此停止，不追加学习率、步数、beta 或新模块搜索。

## 梯度冲突诊断的有限结论

在运行接口矩阵前，对 source 和原 R30 b1 两个状态、两个平台，已计算 19 个反馈观测的偏好梯度。独立 CPU 复算核对 4 个状态、38 条观测梯度记录、166 个梯度对，原 `CPU_AUDIT.json` 通过。

虽然精确非零观测对中约一半是负夹角，按范数计权的负点积能量只占约 0.000000000291%–0.013696%。强梯度主要同向；source 的 keep 梯度为零，其 cosine 未定义，不能当成兼容证据。原 R30 末态 pref 与 keep 的 cosine 分别为 −0.2510、−0.1423，显示纠错与保持之间的权衡。此结果没有支持立即加入 PCGrad 的优先级；只检查 source/末态，不排除中间路径冲突。未因梯度角度删除、重新标记或加权反馈。

## 测量与执行范围

独立审计脚本 `research/round33/independent_audit/audit33_independent.py` 仅运行 NumPy/CPU，使用 A208/DEV64 封存特征与允许的离线任务标签，没有读取 U/FINAL 的样本、媒体或标签。结果见 `audit/AUDIT_RESULT.json`：

- 8 个保存 MLP 状态形状、参数数目、参数变化范数、原反馈与保持集合、原始初始损失均复核通过；1088 个完整分数向量最大 CPU/GPU 误差 1.1844e-6。
- 1088 个保存读出选择逐一复核；从绑定的原始标注重新进行 CPU 几何评分，256 个 DEV 任务值、四行选择表和全部可行性决定一致。
- query 5e-4 两平台状态与 R30 b1 **逐位相同**；A208+DEV64 共 272 条预测 query 与任务 IoU 完全复现。
- 本轮优化器只持有一个独立六数组的 MLP，完整 grounding 模型没有在拟合路径中实例化；其他分支不会被此路径写入。未选中的 text 状态没有另行执行完整模型 GPU 闭环，因此不把缓存头重放称为新全模型推理验证。
- CPU 审计不重跑训练，也不独立复算每一步 AdamW；128 次更新依据已检查的固定循环与封存回执。数据访问边界依据实际审计范围和检查过的控制流，不声称拥有历史系统级文件访问追踪。

原同信息的直接使用反馈、不更新参数，以及 R32 QP memory 等强对照继续保留在既有封存结果。本轮没有产生一个优于旧接口的新候选，因此没有通过扩展确认集重新比较或删掉这些对照。R33 的结论不包含“参数更新优于直接重排”。

本轮裁决：**保留 R30 query 5e-4 为该接口矩阵的参照配置，不采用 text 替换；记录有限负结果，保护 U128/FINAL384。后续机制的选择应以现有总体证据和预登记边界为依据，不能靠回看单个负例修标签或扩大本轮预算。**
