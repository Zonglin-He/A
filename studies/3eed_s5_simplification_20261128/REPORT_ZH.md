# S5-pass 后端简化消融

**可保留的简化候选是 ExtentAnchor8 和 ExtentAttention1。** 前者使用物理区间候选、8 维节点和锚点关系，是删减最多且三套整体点估计均在 2 个百分点容差内的版本。后者保留全连接关系，用单层 Attention 取得更小的整体精度代价。Quad 仍是两者的主要退化来源。

## 对照协议

用相同的 Waymo 3,687 条训练和 768 条验证查询，每条一帧原始输入加四个原协议的扰动视图。仅训练新核验器。所有模型固定 12 个训练轮次的预算，采用相同的 AdamW、风险代价、温度和随机种子，在 Waymo 的 3,072 个退化验证视图上选轮次和单阈值。损坏原本正确锚框的视图数上限为该集合的 1%。2 个目标面板均属历史曝光，分别为开发 665 条和 Mono3DRefer 148 条。完成两份冻结预测后才打开目标标签。S5-pass 保留官方 checkpoint 和阈值，并在 850 条未筛选输入上核对候选池和最终框。 [冻结协议](PROTOCOL_ZH.md) · [聚合结果](results.json)

| 版本 | 改动 |
| --- | --- |
| Anchor | 只计算锚点与各候选的几何关系，宽 128 集合汇聚 |
| Attention1-128 / Attention1-64 | 保留全连接关系，分别用单层宽 128 / 64 的 Attention |
| Nodes8 / Nodes4 | 原三层宽 128，节点缩至 8 / 4 维 |
| No90 | 删除 PCA/Qwen 额外的 90° 候选 |
| Extent | 用观测区间两端替换 0.85 / 1.15 倍尺寸候选 |
| Geometry | 同时使用 No90 和 Extent |
| Adaptive | 固定上一轮局部尺度规则，按新候选重新训练核验器 |
| CompactGraph | 原候选池，8 节点与宽 64 锚点集合汇聚 |
| CompactExtent / CompactNo90 | CompactGraph 分别只叠加 Extent / No90，区分两个规则的作用 |
| Compact | 四尺度，Geometry 与 CompactGraph 结合 |
| CompactAdaptive | Adaptive，Geometry 与 CompactGraph 结合 |

候选变体另测复用 S5-pass 旧权重和阈值的对照。两个 Compact 单项交叉在源域阶段追加，并在读取目标标签前冻结。Extent 以上界为原直立参考框、下界为见证点要求的最小跨度。下界框只在回查 Selection 和 Audit 首交通过时添加。两个端点都受参考框上界限制，尺寸扩张能力与原倍率族存在区别。

- **平台差异。** ExtentAnchor8 在 Quad 上的 Acc@50 从 14.06% 降到 9.38%，ExtentAttention1 为 11.46%。Quad 只有 3 个录制组，Drone 只有 2 个。2 pp 是整体点估计的取舍线。历史曝光、子平台下滑和跨过容差线的置信区间均需要纳入方法选择。 [追加交叉原始聚合](extent_followup.json)

## 候选池贡献

Oracle 用 GT 离线逐例选择池内 IoU 最大的候选。固定旧权重用于观察替换候选池后模型的分布偏移。

| 候选池 | 开发平均框数 | 开发 Oracle mIoU / Acc@50 | Mono 平均框数 | Mono Oracle mIoU / Acc@50 |
| --- | ---: | ---: | ---: | ---: |
| 原候选池 | 10.10 | 42.08 / 47.82 | 8.10 | 43.52 / 50.00 |
| No90 | 8.24 | 40.87 / 45.71 | 6.51 | 43.16 / 50.00 |
| Extent | 9.42 | 41.14 / 45.71 | 7.41 | 43.30 / 48.65 |
| Geometry | 7.56 | 39.85 / 43.46 | 5.81 | 42.92 / 47.97 |
| Adaptive | 8.88 | 40.13 / 42.56 | 7.63 | 41.83 / 47.97 |
| Adaptive + Geometry | 6.61 | 37.52 / 38.35 | 5.64 | 41.33 / 45.95 |

- **固定 90° 姿态。** 单删后开发和 Mono 的最终得分接近 S5-pass，但开发候选 Oracle mIoU 降 1.21 pp，Waymo 退化 val Acc@50 降 2.99 pp。联合删减还会进一步降低候选池上限。
- **固定尺寸倍率。** Extent 重训后的开发 mIoU / Acc@50 变化为 −0.52 / −0.15 pp，Mono 为 +0.72 / +1.35 pp。开发 Oracle mIoU 降 0.94 pp。区间版本为几何证据驱动的候选提供了路径，同时受不扩盒的上界限制。
- **自适应 Bind。** 按新池重训后，开发 Acc@50 从固定旧核验器的 36.09% 升至 36.24%，Mono 同为 37.84%。开发集与 S5-pass 仍差 3.91 pp。两轮实验的自适应候选池逐例一致，批量前向与原单查询前向在开发面板有一项最终框不同。保留四尺度用于简化核验器的后续验证。

## 锚点关系推理及等价目标

锚点关系的描述只计算 $e_{0i}$。每个候选读入自身与锚点特征及显式几何关系，遍历有效候选求平均，再对每个候选评分。候选的锚点相对分数为 $s_i-s_0$。这与全连接消息均值仍需计算所有 $e_{ij}$ 的实现不同。

| 面板 | 查询数 | 全连接关系数 | 锚点关系数 | 关系提取中位耗时 全连接 / 锚点 |
| --- | ---: | ---: | ---: | ---: |
| 开发 | 619 | 73,232 | 6,668 | 0.520 / 0.330 ms |
| Mono | 118 | 11,919 | 1,169 | 0.473 / 0.336 ms |

CPU 单线程使用相同候选重算两种关系布局，计时只覆盖关系特征提取。完全一致的锚点行按逐框数值校验。现有研究脚本在配对准备时仍共用全连接描述缓存。

训练目标可以写成 $U_i'=y_i-0.10\,\mathbf1[y_0>0.5,\,y_i\le0.5]$。对同一查询的所有有效候选减去同一个 $y_0$ 不改变 Softmax 目标。损坏指示项仍取决于锚框。推理使用相对分数和单阈值。

128 组带 padding 的输入上比较新旧目标和反向梯度，FP32 最大概率差为 4.77e-07、损失差为 0.00e+00、梯度差为 3.73e-09。

