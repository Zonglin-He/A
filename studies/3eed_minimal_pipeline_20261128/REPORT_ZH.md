# Bind–Project–Select 流水线消融

把 Correction 与 Fitting 合并为候选内的统一轴恢复，把射线姿态排序放到首次二维分数平局时。物理实例绑定与观测等价几何恢复构成两模块。恢复模块先构造每种姿态的参考框，再以同一个轴区间位移将跨度投影到保护区间。参考框保留原来的证据基准，支持锚与参考框锚分别确定。下游 H/A 与双姿态路径共享同一份相机、标定、回波、像素分桶和 ROI 数据。 [三式论文稿](PIPELINE_ZH.md) · [推理实现](minimal.py)

## 实验协议

873 条历史缓存查询全部盲回放，836 条在封存后计分。开发面板 665 条含 576 条 3EED 与 89 条 KITTI Tracking。外部面板 Mono3DRefer 共 171 条，主对照使用原按录制过滤的 118 条。各面板有历史项目曝光。所有版本共用冻结的两次 Qwen 解码回复及相同传感器输入。尺度减少的工程筛选容限是两套主面板 mIoU 各减最多 0.5 pp、Acc@50 各减最多 1.0 pp，同时保持候选内 Selection 首交。 [预先固定的协议](PROTOCOL_ZH.md)

各版本均新增零模型调用、零训练、零超参。直接参与本实验 Bind、Project、Select 的十项公共门槛以及数值容差保持冻结。报告把可独立配置的尺度切分点单列，共享采样器、地面拟合和标定的常量沿用已有实现。CPU 延迟包括传感器载入和几何计算，使用 i5-14600KF、单进程和单线程 BLAS/OpenCV，交替计时 80 条查询各 3 次。 [汇总数据](results.json)

## 复现

`minimal.predict(frame, replies)` 的默认四尺度配置即 Minimal-D。使用已恢复的项目虚拟环境和历史封存缓存，在仓库根目录运行。GitHub 提供独立重构与汇总结果，逐例 RGB、LiDAR、回复、评分和历史恢复辅助文件沿用本地工作区。原产物目录已有封存文件时用独立工作区回放。

```bash
study=studies/3eed_minimal_pipeline_20261128
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
python "$study/replay_minimal.py"
python "$study/time_backend.py"
python "$study/score_minimal.py"
```
