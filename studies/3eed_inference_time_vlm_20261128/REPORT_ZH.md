# 冻结 Qwen3-VL 的四项推理期几何实验

**四个方向均完成配对实测。** 物理中心可以在 Qwen 解码过程中有效纠正原生框，但同后端对照没有额外收益。Quad 的严格物理筛选 ICL 提高了该平台的 mIoU 和 Acc@50，全平台汇总低于正式基准。SoM 的主要损失在可展示提案的覆盖，度量场景图在固定提案上没有体现增量。[完整分项与置信区间](results.json)

## 实验设计

从已曝光的 702 条 3EED 主面板按平台、录制和固定哈希选取 96 条查询，每条来自不同 RGB 路径。Waymo、Drone 和 Quad 各 32 条，分别来自 32、2 和 3 段录制。四个方向在同一批查询上配对。先锁定成员、提案、中心前缀和示例库，再封存所有 Qwen 输出与几何读出，最后读取目标 GT 评分。物理提案和 ICL 示例筛选均不用目标标注。所有模型调用使用同一份冻结 Qwen3-VL-4B-Instruct。正式基线使用冻结的 `ray_equivalent_height_only_2d_rank`，在 96 条上与此前封存结果逐条核对。mIoU 与 Acc@50 计入无框，阈值采用正式评估的 IoU > 0.50。95% 区间对平台内录制做 2,000 次配对重采样。Drone 和 Quad 的区间只能描述当前少量录制。[冻结协议](PROTOCOL_ZH.md)

RGB 文件内容核验发现 Drone 同一录制内两对逐字节相同的图像，因此主分析是 96 条查询、94 张不同 RGB 图像。12 张用于示例的不同 RGB 与测试图像无内容重合，录制也无交集。每组重复图像仅保留封存序列中第一条后，正式方法为 35.96% mIoU，物理权重树原生为 23.03%，物理筛选 ICL 加后端为 33.15%，SoM 为 22.67%，场景图为 22.20%，主要对照方向一致。去重复算未重选示例或补入新样本。[内容审计与复算](audit_replay.py)

## 四项配对结论

### P1 · 物理引导解码纠正了中心，几何后端已吸收主要收益

在 94 条能构造候选中心的查询上，物理权重改变了 79 条中心选择。相对固定物理锚的中心距离中位数从 2.87 m 降到 0.007 m。和均匀 token 树对比，原生 mIoU 提升 **17.60 pp**，95% 区间 **[14.25, 21.07]**。加同一几何后端后，差值为 **−0.52 pp [−1.32, 0.20]**。

在原中心前缀和物理中心前缀均可解析的 85 条上，中心误差中位数由 5.35 m 降到 0.44 m。轴向 yaw 误差的配对均值降低 5.21°，95% 区间 [−8.02°, −2.55°]。长宽高平均相对误差的配对变化为 +0.04 pp [−0.93, 0.95]。直接与同视线错误深度比较的 81 条补充分析中，正确物理前缀的尺寸误差低 1.46 pp [−2.64, −0.31]，yaw 差为 −1.18° [−4.50°, 2.01°]。因此，yaw 改善相对原中心对照成立，能否归因于正确深度仍不确定。物理中心前缀加同后端是 32.60% mIoU。数值树衡量有限候选上的解码控制。

### P2 · LiDAR-first SoM 的主要限制是提案进入前八

全池 4,006 个提案中，按目标框内支持点代理，85/96 条可以找到合格提案，展示前八后只剩 51/96。SoM 在这 51 条中选中 47 条，首次 Qwen 框选中 46 条。与同池首次 Qwen 2D 框相比，SoM 的 mIoU 差是 −0.34 pp [−1.90, 1.13]，Acc@50 差为 −1.04 pp。只更换数字后有 16/96 条换了提案。展示提案的离线 IoU Oracle 也只有 22.92% Acc@50，正式方法是 34.38%。固定选择并改用纯测量框的 SoM 为 12.31% mIoU、6.25% Acc@50。

### P3 · Quad 有局部正向结果，平台适应尚未普遍成立

| 目标平台 | 通过初筛的候选示例 | 严格合格 | 入选严格 / 总示例 |
|---|---:|---:|---:|
| Waymo | 100 | 0 | 0 / 2 |
| Drone | 76 | 0 | 0 / 2 |
| Quad | 48 | 2 | 2 / 2 |

Quad 上，严格物理筛选加同后端相对新零样本高 **3.06 pp mIoU [1.62, 5.01]**，相对正式方法高 **1.65 pp [0.81, 2.62]**，Acc@50 从 3/32 到 4/32，变化区间 [0.00, 10.00] pp。Quad 原生输出相对零样本的 mIoU 区间为 [−3.69, 10.77] pp。该平台只含三段评分录制。

跨三平台，筛选示例加同后端相对随机示例高 **3.19 pp [1.93, 4.59]**，相对新零样本低 **2.03 pp [−4.29, 0.19]**。Waymo 和 Drone 使用宽松补足，该臂衡量的是宽松筛选的效果。跨平台对照的严格示例比例随目标平台变化，不能单独归因于同平台。零样本 93/96 可解析，三种双示例均为 96/96；格式收益未转化为全局几何收益。

### P4 · 度量场景文本未改善同池选择

正确度量图、错配图和只显示数字均选中 47/96 条符合目标支持代理的提案。正确图相对只显示数字的 mIoU 差为 −0.46 pp [−1.44, 0.15]。错配图导致 12 条换选，正确图的整体结果仍低于错配。预置的宽口径关键词在 96 条中全部触发，因此不能据此区分关系与非关系表达。采用显式相对短语的 59 条事后对照，正确图与错配图的 mIoU 和 Acc@50 相同，正确图相对只显示数字为 −0.75 pp [−2.40, 0.24]。图选 ID 后再生成尺寸和角度，相较共用补全框损失 **5.78 pp [−8.46, −3.30]**。

## 推理开销

四方向合计 15 个对照、1,430 次模型读入，峰值 CUDA 已分配显存约 11.87 GiB。SoM 数字选择为 0.145 秒/条，度量图选择约 0.186 秒/条，图上补全再增加约 0.619 秒/条。ICL 是一次含三张图的模型读入，约 1.08 秒/条；同提示零样本约 0.62 秒/条。物理 token 树与均匀 token 树分别约 0.596 和 0.592 秒/条有效输入。这些是单卡批处理的张量预处理与模型墙时。

## 实现与复跑

- P1 固定原生中心、正式 RGB–LiDAR 锚定中心、同射线乘以 1.4 的反事实中心，改变 JSON 助手前缀后续写尺寸和欧拉角。相同候选集上的 token 约束另外做两次，比较均匀分支质量和物理分支质量。每个候选中心的对数质量为 $-\min(20,\lVert c-c_L\rVert^2/(2\sigma^2))$，$\sigma$ 由真实回波深度的稳健尺度给出。对前缀 $u$ 及有效下一 token $v$，在原 logit 上加 $\log M(uv)-\log M(u)$，其中 $M$ 为相应子树的先验质量。中心结束后恢复普通贪心。条件中心来自现有正式框，包含既有 Qwen 证据。
- P2 用完整相机视野的 LiDAR 复用四尺度非地面连通域，只由点和标定生成并排序，去重后标记前八个。以同池内的原 Qwen 窗口匹配、SoM 数字选择、换号后回映射对照。每个候选的几何读出在不同选择臂间固定。补全版尺寸共用首轮 Qwen 先验，纯实测框另列。身份以抽样支持点中至少五点且至少 50% 位于目标 GT 框内为评分代理。
- P3 三种两示例上下文分别用同平台哈希随机、同平台物理一致性筛选、跨平台物理一致性筛选，与同格式新零样本对照。物理闸门用独立 Audit 回波构成的相机视点代理射线和投影框。预测阶段不读取示例真值，伪框的协议仅保证所测一致性。所有示例均排除目标测试录制和相同 RGB。候选不足两条时按协议排序补足。
- P4 保持 P2 的图像和提案，注入相机坐标、实测跨度、离地高度以及相对近邻关系。对照无文本图与错配 ID 属性。空间关系子集由描述中的方位、远近和邻接词预先定义。完整几何读出先由图选 ID，再用所选候选补全框的中心前缀生成尺寸与角度，共两次模型读入。

运行环境为 RTX 5090、Python 3.12.16、PyTorch 2.15.0+cu132、Transformers 4.57.1，使用 BF16 与贪心解码。Qwen3-VL-4B-Instruct 快照为 `ebb281ec70b05090aa6165b016eac8ec08e71b17`。实验脚本复用仓库的冻结推理环境、已有 3EED/历史 KITTI 输入回执，以及 `runs/cascaded-oracle-20261128`、`runs/2d-relocalization-20261128`、`runs/pedestrian-paired-recheck-20261128` 的已封存本机输入。缓存保存在 `runs/inference-time-vlm-20261128`。运行顺序如下，每步是独立进程。

```bash
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
STUDY=studies/3eed_inference_time_vlm_20261128
python "$STUDY/prepare.py"
python "$STUDY/infer_controls.py"
python "$STUDY/evaluate_inference.py" geometry
python "$STUDY/evaluate_inference.py" score
python "$STUDY/audit_replay.py"
```

GPU 状态支持按已封存的输入和脚本哈希续跑。公开结果的配对指标为全样本端到端对照，参数误差对比只取参与比较的两臂都能解析 3D 框的查询。协议、结果和复跑脚本随报告发布。RGB、点云、逐例预测和标注留在本地。[数据准备](prepare.py) · [冻结模型推理](infer_controls.py) · [封存与评分](evaluate_inference.py)
