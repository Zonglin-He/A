# HiSpatial 单模型物理区域自定位

本轮验证冻结的 HiSpatial-3B 能否把 EmbSpatial-Bench 近／远题的选项物体绑定到同一张 MoGe-2 点图上的可见物理区域。沿用前次错因诊断的 1,206 道题及 897 张图像，所有正例和负例进入原任务评分。输入使用选项物体名，点图与上一轮封存的对齐 MoGe 一致。该入口仅加载 HiSpatial-3B 及其 MoGe-2 权重，推理直接复用封存点图。新增可训练参数和更新步数均为零。 [运行配置](PHYSICAL_SELF_GROUNDING.json) · [上轮诊断](GEOMETRY_DIAGNOSIS_ZH.md)

## 物理区域与对照设计

候选区域来自四个尺度的图分割。邻接图的特征由 Lab 颜色、相对相机深度和归一化 XYZ 射线构成。每个候选还须在相对 XYZ 步长限制下保持连通。完整候选库留作离线覆盖诊断，推理时按边界显著性、区域紧实度、大小与位置多样性展示至多八个高亮区域。同一 HiSpatial 根据选项物体名选择区域字母。每个绑定保存有效三维点数、可见质心、区域内平均深度和包围窗口的平均深度。实验只验证可见区域绑定与深度。 [经典图分割](https://www.cs.cornell.edu/~dph/papers/seg-ijcv.pdf) · [区域标记提示](https://arxiv.org/abs/2310.11441)

| 比较 | 读出 |
|---|---|
| 原始 HiSpatial | 采用上轮封存的原图＋同一对齐 MoGe 点图回答 |
| 全图深度 | 在整张图上叠加暖近冷远的相机深度颜色，与同一 XYZ 一起输入冻结 HiSpatial |
| 二维窗口深度 | 使用自定位选中的同一批区域，直接计算它们包围窗口内的有效深度均值 |
| 物理区域深度 | 保留同一批绑定，用各区域的三维连续支持点计算深度均值 |

两种对象级读出共用同一触发条件。所有有具体对象名的选项均绑定到不同区域，且两种深度读出各自有唯一极值时，才按题意取最近或最远。其余保留原始 HiSpatial 回答。抽象 `Unknown` 选项仍保留在官方评分中。三维场景区域和二维窗口对照包含相同物体名称、框范围及触发覆盖。近／远的原始官方标签根据物体框内平均深度生成。 [EmbSpatial-Bench 论文 §2.1](https://aclanthology.org/2024.acl-short.33.pdf)

## 全量评分

| 方法 | 最近（612 题） | 最远（594 题） | 合计（1,206 题） |
|---|---:|---:|---:|
| 原始 HiSpatial | 67.32% | 62.96% | **65.17%**（786） |
| 全图深度着色＋HiSpatial | 61.44% | 58.42% | 59.95%（723） |
| 同绑定二维窗口深度 | 65.85% | 61.78% | 63.85%（770） |
| 同绑定物理区域深度 | 66.01% | 62.12% | 64.10%（773） |

物理区域相对原始 HiSpatial 救回 3 题、损伤 16 题，净变化 −1.08 个百分点，按场景聚类的 95% 区间为 [−1.87, −0.43]。相对同绑定二维窗口，区域掩码有 3 题改对、0 题改错。实际使用对象级深度读出的只有 45 题，原模型在其中答对 34 题，区域读出答对 21 题，窗口读出答对 18 题。1,143 题发生重复区域绑定，18 题存在未匹配选项。 [配对准确率与救回／损伤](results/physical_self_grounding_20261121/paired_accuracy.csv)

## 绑定瓶颈

| 4,675 个有标注的具体选项 | IoU ≥ 0.25 | IoU ≥ 0.50 |
|---|---:|---:|
| 完整区域库中存在达标候选 | 4,413（94.40%） | 2,853（61.03%） |
| 展示给模型的区域中存在达标候选 | 2,795（59.79%） | 1,298（27.76%） |
| HiSpatial 选择了达标区域 | 902（19.29%） | 453（9.69%） |

按 0.25 分界，262 个选项在完整区域库中缺少达标框，1,618 个有达标框却未展示，1,893 个展示了达标框却未被选中。选择结果比同题打乱绑定的期望命中数高（902 对约 595）。以不同区域分别匹配每个对象为要求，1,206 题里完整区域库有 977 题具备机会，展示八区后还剩 107 题，实际所有对象匹配达标只有 2 题。上轮已知的 130 道「给框即能稳定读对深度排序」错题中，当前完整库有 110 题可覆盖全部对象，展示后只有 8 题，最后没有救回题目。

八区域提示的 4,655 个有效绑定中，4,653 个选择 A–D，只有 2 个选择 E–H。这使 981 个达标候选只在后四个区域中的选项在实践中很难被读出。96 题的字母反转对照中，375 个具体物体在两次提示中都选出区域，只有 1 个指向同一物理区域。候选截断和标记选择都需要对最终绑定负责，区域深度与窗口深度的差异发生在更靠后的阶段。

## 分组标记复核

前 443 条八区域提示的原始输出没有选择 E–H。根据这个无标签现象，在同一批 96 题上保留相同八区候选，将它们分成每次至多三个区域的子组，并提供拒绝选项。多个子组给出区域时，再让同一个 HiSpatial 在子组赢家中选一次。分组同时缩小了选项数和同屏高亮范围。

| 379 个可核验对象选项 | IoU ≥ 0.25 命中 | IoU ≥ 0.50 命中 |
|---|---:|---:|
| 一次展示八区 | 65 | 26 |
| 分组保留下来的候选（最终选择前） | 128 | — |
| 分组后最终选择 | 81 | 42 |

分组最终在 IoU 0.25 上救回 40 个物体绑定、损失 24 个，仍有 47 个在分组时保住的正确区域未通过最终选择。96 题中，19 题获得不同的区域 ID，所有对象都达到 IoU 0.25 的题数为 0。本轮结果支持将候选展示与对象绑定视为当前瓶颈。单模型原型保留用于研究，任务输出仍以原始 HiSpatial 为基线。 [完整结果与运行核验](results/physical_self_grounding_20261121/SUMMARY.json)

## 复现

先取得 [官方基线](README.md) 和 [错因诊断](GEOMETRY_DIAGNOSIS_ZH.md) 的本地封存产物。候选生成还需要 SciPy、OpenCV 和 scikit-image。以下命令从仓库根目录运行，预测和离线核验可使用前两轮相同的 Python 环境。

```bash
study=studies/hispatial_zero_shot_spatial_reasoning
assets=/path/to/model-cache
python "$study/object_region_plan.py"
python "$study/object_region_infer.py" --model-cache "$assets"
python "$study/object_region_panels.py" predict --model-cache "$assets"
python "$study/object_region_audit.py" --official-source "$assets/sources/HiSpatial"
python "$study/object_region_panels.py" audit
```

物体框与正确答案只在封存预测后的 CPU 分析中使用。原始模型回复、逐题回退、候选框坐标、区域掩码和样本核验留在本地 `outputs/hispatial_physical_self_grounding_20261121/`。
