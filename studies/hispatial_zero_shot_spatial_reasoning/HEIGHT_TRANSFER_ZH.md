# 冻结 HiSpatial 的首交等价高度修正

本轮在 SpatialRGPT-Bench 的 Region-Given 协议下隔离对象几何。冻结 HiSpatial-3B 和 MoGe-2，沿用官方脚本的彩色对象框与原始图像点图。评测包含验证集全部 133 道 Height 和 133 道 Width，涉及 217 张 RGB 图像与五个数据来源。原 Qwen 路线的主方法和本轮数据、模型各自独立。[Qwen 方法登记](https://github.com/Zonglin-He/A/blob/dbd38fe61a637b6ae2905ec67d1b5fa535f7a349/QWEN_CURRENT_METHOD.json) · [HiSpatial 官方输入](https://github.com/microsoft/HiSpatial/blob/9b0a5718ed0fb3b8bd9d9e0b36b6192bd3e99be1/eval/eval_spatialrgpt.py) · [SpatialRGPT-Bench 固定版本](https://huggingface.co/datasets/a8cheng/SpatialRGPT-Bench/tree/01b38d2c7aa805223518c061f2a7602ad8f491ef)

## 几何与对照

1. **R0** 从原始问法得到 Native 回答，再使用两条预定的高度问法，记录主先验和改写稳定性。Width 题也单独读取所标对象的高度，用于高度证据的负对照。
2. **R1** 对齐原分辨率像素的 Fit、Selection 和 Audit 三个集合。用 Fit 点估计下半图的场景平面，经空间覆盖、角度和残差筛选后将法向作为竖直轴。复用四尺度 MoGe 候选库，按官方矩形 IoU 选区，在矩形内读取 Fit 支持。未检测到可靠平面或者支持不足时回退。
3. **R2** 用 Fit 支持拟合无填充 PCA 有向框，将八个角点外包成相对于估计竖直轴的直立框 \(B_0\)。这个初始框不读取数值先验。对物理点跨度、初始直立高度、仅保护点的收缩与首交等价收缩分别评分。
4. **R3** 同一个模型读取原始 RGB、原 MoGe XYZ 和文本证据。增加主先验数字、修正后高度数字、初始几何状态、修正后几何状态四组。后两组只替换完整高度。无对应数值或几何时使用原回答。

设 \(z_b\) 为固定底面，\(H_S\) 为初始框内的 Fit／Selection 点及 Selection 首交点的最大高度相对底面。公式为
\[
h' = \min\{h_0,\max(h_{\mathrm{prior}},H_S+10^{-7}\text{ m})\}.
\]
新框包含旧首交点且属于旧框的子集，所保护的命中射线有相同的首次相交位置。初始未命中的射线仍然未命中。实际程序逐条复核该不变量，Audit 像素只用于事后检查。三套像素来自同一个 MoGe 点图，统计误差可能相关。场景法向是视觉估计的竖直参考，框尺寸仍依赖可见范围及尺度预测。[预封存协议](HEIGHT_TRANSFER.json) · [SpatialRGPT 论文附录 K 的有向框讨论](https://papers.neurips.cc/paper_files/paper/2024/file/f38cb4cf9a5eaa92b3cfa481832719c6-Paper-Conference.pdf)

评分使用论文的 ±25% 成功率和绝对相对误差。全部问题进入成功率分母，ARE 对可解析值和配对共同可解析值分别汇总。论文用 GPT-4 提取并换算数值，本轮使用固定的本地单位解析器，保留数值解析覆盖率。先封存预测再打开参考回答。[SpatialRGPT 论文评测说明](https://papers.neurips.cc/paper_files/paper/2024/file/f38cb4cf9a5eaa92b3cfa481832719c6-Paper-Conference.pdf)

### 初始框确有冗余，首交等价无法保证高度正确

- 133 道 Height 中，91 道建立了有效初始框。其中 37 道因缺少有足够支持的场景平面回退，3 道缺适用区域，2 道 Fit 点不足。有效框的初始高度与可见跨度之比中位数是 1.424。外包顶面比最高 Fit 点高出中位 0.154 m，底面比最低 Fit 点低中位 0.159 m。底面在缩顶时固定。
- 69 道题触发缩顶，占全体 51.88%。中位收缩 0.181 m。只有 3 道收缩后的高度等于 HiSpatial 原生先验，说明算子确实受观测边界约束。改变的 83,851 条 Selection 射线中，83,850 条原本命中，全部保持命中状态及首交深度。Held-out Audit 共 83,413 条，有 1 条改变命中、4 条改变首交深度。Width 的 56 道触发题也保持全部 73,371 条 Selection 射线，Audit 的 73,194 条中有 2 条改变命中。 [逐行几何复放](results/height_transfer_20261122/GEOMETRY_REPLAY.json)
- 91 道有效 Height 题上，初始框、首交等价、可见跨度和原生先验分别成功 **33、48、74、82** 道。初始高度与真实高度之比中位数从 1.395 降至 1.237，修正后仍有 41/91 道高估超过 25%。同一批题直接用可见跨度或原生先验，高估超过 25% 的数量分别为 7 和 6 道。
- 去掉首交见证，只保护测量代理点，准确率为 53/91。首交约束把 43/91 道题的顶面限制在更高位置，代价为 5 道 ±25% 成功题。点保护对照对相同 Selection 改变了 12,439 条共同命中射线的首交深度。该对照表明，保住已经建立的框表面会保留部分外包偏差。
- 原生高度先验两个预设问法均可解析 133/133，132 道的改写差异在 25% 以内，中位相对差异 2.49%。主先验比原题多成功 8 道，救回 10 道、误改 2 道，按图像聚类的 95% 区间为 [+1.48, +11.28] pp。原生先验是本轮比完整框重建更强的对照。

### 问答增益来自简单的数字接口

- 原题加修正后的单个高度数字成功 116 道，比原题多 5 道。直接加原生高度先验成功 117 道。两种数字提示在共同的 91 道可修正题上各成功 81 道。全体配对中，以修正数值替换先验数值救回 2 道、误改 3 道。这个结果没有给首交裁剪提供独立问答增益。
- 完整修正状态的输出仅 70/133 可用固定数值解析器读出。63 条不可解析输出中，54 条有多个带单位的数字。逐条读取明确标为目标物体完整高度的字段，能把成功数从 59 道提高到 81 道，仍低于原始问答的 111 道。该分析只对已经封存的回答更换提取规则，主表维持固定解析器。
- Width 的水平边界逐项相同。追加修正高度数字时，宽度原题成功数从 93 降至 84，完整状态降至 66。更好的高度值、首交保证与模型能否读懂几何提示是三个独立判断。

**本轮裁决。** HiSpatial 的 MoGe 代理框有自然的可缩减余量，且首交约束可以实测复现。当前这套 Height-Only 迁移在高度准确率和最终问答上均没有超过同信息下的原生先验。该配置停在 Region-Given 机制诊断。结论适用于冻结 HiSpatial、给定区域和本次以场景法向为竖直参考的初始框。

## 执行与复现

266 个原问题提示与官方渲染逐字符一致。实际运行 708 个原问／先验调用、717 个几何提示调用，另做 24 个单题与批量对照。12/12 原问生成一致。RTX 5090 正式推理及几何处理共 516 秒，峰值 CUDA 分配约 18.10 GiB。预检发现 GPU 环境缺少区域构造依赖，独立安装 scikit-image 0.26.0 后复跑。全部预测散列核验通过，另用 CPU 复放了 266 条几何记录。

从仓库根目录运行，使用官方基线 README 的同权重推理环境及单独的 scikit-image 0.26.0。CPU 环境需 PyArrow、NumPy、SciPy、OpenCV 与 Pillow。各阶段原始响应、几何状态、封存和逐题评分保存在 `outputs/hispatial_height_transfer_20261122/`。

```bash
study=studies/hispatial_zero_shot_spatial_reasoning
assets=/path/to/model-cache
cpu_python=python
gpu_python=python

"$cpu_python" "$study/height_transfer.py" fetch
"$cpu_python" "$study/height_transfer.py" prepare
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  "$gpu_python" "$study/height_transfer.py" predict --model-cache "$assets"
"$cpu_python" "$study/height_transfer_audit.py"
```
