# R48：固定缓存的主体跨度与官方读出诊断

**P0 未发现“当前主体跨度选错”能解释这批开发缓存低分。** 冻结依存解析在 310 条观测找到主体 head，26 条 UNKNOWN 回退；最终 336 条有效正 token mask 全部与原代理一致。因此参数、候选框、输入表示不变时，主体解析分支没有改变任何候选分数或 Top-1，而非只是碰巧总体均值相同。

官方类别辅助读出在 126 条改变 mask，26 条改变 query，但平均 mIoU 下降 0.170609 个百分点。两种官方索引处理在全部 336 条产生相同 mask，首空格引起 token-index 错位的竞争解释在本缓存上没有触发。这轮削弱了把“主体读出错误”排在首要瓶颈的假设；据此撤低此前把主体跨度列为首要嫌疑的判断，不据此追加解析规则或 TTA 损失。

## 固定条件与信息边界

数据仅为此前已暴露的 D208、V64、M64，互不重叠共 336 条，Drone／Quad 各 168 条，来自 2 个 Drone 和 3 个 Quad 已知场景。全部属于开发诊断，不能当作新场景或全研究史未接触的确认。本轮未访问已关闭 FINAL384 的任何清单、预测、输入或标签，也没有改写或重评 R46。

所有新读出使用同一份缓存 query、token embedding、源框与温度 0.07，在实际 T 上计算一次 CPU64 softmax。保留 BOS／EOS／sentinel 的分母，按布尔正 token mask 求和；不补零 logits 后重新 softmax，不再归一化 embedding，不重编码文字。历史 native 分数作为第五个精度桥接臂单列。

解析仅接收 caption 和冻结 Stanza CPU 依存结果。head-only 主 mask 包含该词全部 BPE，compound 只记录诊断。全体解析先封存，才允许官方两臂通过历史精确 object_index 的 class／caption 白名单读取标注类别。全部五臂预测再封存，独立 CPU 审计 PASS 后，root 另授权一次统一 GT 框评分。类别信息不进入文本解析或其 UNKNOWN 回退。

官方两臂按原训练快照的类别→平台同义词表优先级→第一个匹配构造正 token mask。literal 臂把官方首尾空格文本的 token 索引字面用于实际缓存；remap 臂固定同一字符跨度，只扣除前导一字符偏移再映射实际 tokenizer。它们使用标注类别，是跨度诊断，**不是 oracle、可部署方法或完整官方模型复现**。

## 变化发生在哪里

原代理与文本解析的有效 mask 336／336 完全相同。其中 310 条来自 parser 自己接受的 head，另 26 条来自声明为 UNKNOWN 的原代理回退。**不能把这写成 parser 独立成功 336 条，也不能将零收益解释为优化器没有执行——本轮根本没有拟合或参数更新。**

官方与原代理的 mask 有 126／336 条不同，Drone 88 条、Quad 38 条。固定预测的逐条分解表明，这 126 条都满足：原代理选中的词也在同一标注类别的同义词表内，但官方按表中词项优先级选了文字中更晚出现的另一同义词。其余 210 条 mask 相同。这里记录的是可重放的字符串／词表选择机制，不自动将两个词认定为同一视觉实例或正确目标。

这 126 条中有 26 条改变 Top-1：Drone 18、Quad 8。它们带来 2 条 IoU 改善、8 条恶化、16 条 IoU 不变；全部保留。26 条 query 改变不等于 26 次实例身份改变，IoU 变化也不能单独认证语义身份。

literal 与 remap 的正 token mask 差异为 0／336；历史 float32 native 与共享 CPU64 原代理的 Top-1 差异也为 0／336。这分别约束本缓存的索引错位解释与有限精度决策解释，不证明所有文本形式、tokenizer 或平台都没有此问题。

## 审计、成本与失败保留

独立审计重放全部 336 条依存规则、官方 span／二值 mask、共享概率、5 组完整分数和 1680 个选框，概率与分数最大误差均为 0.0；无缺失依存词 offsets，耗时 4.304 秒。唯一任务评分耗时 0.695 秒。

解析阶段程序记录 15.490 秒，预测读出阶段 5.408 秒；它们是本地 CPU 批处理成本，不能作为单条部署延迟。新增 grounding／VLM forward、GPU 调用和优化步数均为零。

首版纯合成检查发现：缺失真实 head offset 时，过滤该词会错误晋升 compound。原失败与未执行锁保留；真实 NLP／类别读取前登记唯一 schema 安全修复，缺失或非精确名词 offsets 直接 UNKNOWN。同一六项纯合成检查随后通过。独立审计首次 shell 启动使用不存在的 Python 路径，guard／程序均未启动；原日志保留，改用已配置解释器后同代码通过。这两类失败都不涉及依据任务结果改规则。

缓存没有保存历史 input_ids。重建 tokenizer 长度、offset 和原代理 mask 的精确桥接，不等于历史 token IDs 已逐位证明；能直接保证的是原 query／tokens／框缓存未改。

## 裁决

**不采纳新的主体解析作为性能升级，也不切换到官方类别辅助读出。** 本轮 parser 的有效输入 mask 与原代理完全一致；官方词表优先级修改在已暴露开发集略有退化。当前证据不支持用新的主体 head 规则或 TTA 损失去解释和修复既有总体低分。本轮只测 source 的固定读出，没有重跑 R24／R30 适应，不能推断它们在其它读出下的 TTA 差值。保留原代理与所有诊断输出，不修改已经关闭的最终方法和结果；若以后研究更完整的属性／关系语义，须另行建立可区分的反馈与实验，不能把本轮零变化当作这些更广泛机制的检验。
