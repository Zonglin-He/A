R10 RGB support is a pure supplied-array classical GrabCut observation module. `make_rgb_support(*,rgb,points_fit,source_box6,camera_spec,config=RGBSupportConfig())` returns a boolean full-image mask, `valid`, and diagnostics. It does not read metadata, GT, captions, scores, models or files. It consumes the original frozen q0, without reselection. The runtime environment supplies OpenCV 4.11.0; no dependency environment was modified.

The canonical default config has context fraction .25, context minimum 4 pixels, outer sure-background border 2 pixels, minimum ROI side 8 pixels, minimum 5 unique foreground and 5 background seed pixels, 5 GrabCut iterations, minimum depth .1, and 8-connected foreground components. Continuous FOV filtering precedes floor rasterization. Per-pixel nearest-depth selection uses only the supplied points, with XYZ tie-breaking. Hard foreground seeds come from visible supplied points inside q0. All-corner positive-depth and ROI requirements fail closed. The chosen component maximizes seeded pixel support, then area, then the smallest component index. An unsupported mask is explicitly invalid and all zero; this zero mask is not a synthesized observation of background.

The wrapper's deterministic OpenCV seed is a hash of the q0 float64 bytes and image height/width. It does not use colors, labels, task scores or case outcome. Crop RGB is converted to BGR only to meet the OpenCV interface. There are no color-to-category rules. Synthetic repeat, channel-permutation, projection, failure and split checks establish engineering mechanics, not task-quality evidence.

Current firststage uses the whole allowed observed point set. The source model sampled 16384 rows with replacement. The root runner passes exact unique XYZ to RGB/G and keeps the first corresponding raw index; support counts do not count replacement duplicates as independent points. The saved optional split hashes canonical float32 unique XYZ. Distinct raw observations with identical XYZ are conservatively paired into one role, so it is not an independence proof. A future heldout claim requires grouping raw observation IDs before replacement and using fit-only points throughout visibility/segmentation/fitting. Source q0/backbone and the RGB image remain shared; these are within-frame observations, not independent views or scenes.

The mask may include nearby objects, background, multiple seeded components, or the wrong q0 instance. GrabCut support is not semantic identity or calibrated object probability. Full RGB and no-RGB-coordinate geometry controls must share the exact same RGB-filtered point support and acceptance mask; only the RGB coordinate constraint differs. The pointmask ablation is a separate capability group.
