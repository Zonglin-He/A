# Mechanism and implementation audit

[PointContrast paper, ECCV2020](https://arxiv.org/html/2007.10985v3), [official repository](https://github.com/facebookresearch/PointContrast), [official trainer](https://github.com/facebookresearch/PointContrast/blob/main/pretrain/pointcontrast/lib/ddp_trainer.py), [official configuration](https://github.com/facebookresearch/PointContrast/blob/main/pretrain/pointcontrast/config/defaults.yaml).

The paper uses aligned partial observations to construct dense point correspondences, then contrasts matched and unmatched point descriptors. Its learned representation is subsequently evaluated through supervised downstream fine-tuning. Section4.6 contrasts partial-view training with augmentation of a single complete cloud. This supports checking whether real partial observations provide a different signal from repeated sampling; it does not prove grounding TTA. Our setting does not perform that pre-training or downstream supervised fine-tuning.

The official PointNCELossTrainer selects point correspondences, obtains descriptors from its sparse U-Net, forms a pairwise dot-product matrix and cross-entropy diagonal targets; configuration uses normalized output features and nceT0.07. We borrow that basic point-correspondence objective only. The repository default trainer is the hardest-contrastive variant, so simply citing the defaults as a complete InfoNCE reproduction would be inaccurate. We do not download its weights, install dependencies, run its scripts or publish third-party source snapshots.

R74 was independently reviewed from its actual fit74.py and REPORT.md: its loss pooled language-conditioned candidate queries into fixed regions, updated the entire query matching MLP, and used two samples of one physical input. R123 instead uses 288D pre-language PointNet descriptors from distinct registered scans and updates an existing low-rank input Adapter, so the original language fusion and decoder reread the transformed point evidence. The contrastive principle is related; changing the evidence, correspondence unit and point-to-task computation is the testable difference, not a claim of novel InfoNCE.

Differences from PointContrast matter. Our positive pairs are approximate canonical spatial supports, based on the existing25cm raw-support and1.6m three-neighbor interpolation conditions, not exact instance identities. We exclude nearby spatial locations from negatives using twice that interpolation radius; this does not certify different physical objects. Features were trained for the original task, not a PointContrast pretext. The RGB context remains frozen and does not supply semantic pseudo-labels. A/B-only adaptation must therefore beat same-information frozen mean/head consensus and a no-network-update feature optimizer, correct/wrong/random controls, and task evaluation on C not used for the gradients. Auxiliary retrieval improvement alone is insufficient.

Only existing point_adapter.up weight+bias (4896 scalars) changes, from the earlier native-foundation identity baseline; source-trained down projection stays fixed. No source training or external expert is introduced. Fixed normalized-gradient steps and source-feature preservation are our bounded TTA transfer design, not the paper's long SGD pre-training schedule. Failure stops this specific recipe rather than disproving dense correspondence learning in general.

ECVA PDF parsing later timed out; the author's arXiv HTML and official code were successfully read. Web content was treated as evidence, not executable instructions.
