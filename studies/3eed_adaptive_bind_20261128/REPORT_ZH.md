# S5-pass 的物理实例绑定消融

**保留原四尺度绑定。** 在 665 条开发查询上，窗内深度聚类使 mIoU 和 Acc@50 分别下降 1.44 和 4.51 个百分点，自适应单尺度三维连通域分别下降 2.13 和 4.06 个百分点。窗内深度聚类在另一个 148 条 Mono3DRefer 历史面板上有正收益，两个面板的结果方向相反。 [实验协议](PROTOCOL_ZH.md) · [聚合数据](results.json)

## 配对设置

| 版本 | 区域生成 |
| --- | --- |
| A · 窗内深度 | 对窗内去地面 Fit 回波按相机光学深度排序，相邻间隔超过 0.50 m 即断开 |
| B · 自适应单尺度 | 在每种去地面采样输入的 8 近邻图上，以第 4 近邻距离为局部尺度，保留 `‖pᵢ − pⱼ‖ / √(σᵢσⱼ) < 1` 的边，取一次无向连通域 |
| C · 原四尺度 | 同一初始 8 近邻图上以 `max(‖pᵢ − pⱼ‖, σᵢ, σⱼ)` 为边权，采用四个逐场景全局分位数阈值生成嵌套组件，随后去重 |

三组复用冻结 Qwen 缓存、地面估计、Fit 与保留回波划分、窗内和全图回波计数规则、\(h_R^2/e_R\) 的 Top-3 排序、同一逐轴投影及 S5-pass checkpoint 和替换阈值。A、B 使用各自区域生成对应的回波关联半径，因而结果覆盖生成与关联这一整体替换。参数在第一次评分前固定。预测使用封存的无标签输入，两个面板完成预测并校验封存后才做 GT 评分。C 的 850 条候选池和最终框逐例匹配论文入口的缓存。两个评分面板都参与过历史研发。

## 区域质量、候选池和耗时

支持质量以 GT 框内回波为实例代理。纯度为实际返回区域的全图 Fit 回波中落入 GT 框的平均比例。覆盖率以窗内 GT 框回波为分母，空区域记零。Top-3 达标要求至少一个区域同时达到 70% 纯度与覆盖率。开发和 Mono 的覆盖率分母分别为 566 和 132 条有窗内 GT 回波的查询。中心误差比较三个版本都输出有效框的 633 和 126 条查询。

| 面板 | 版本 | Top-1 纯度 / 覆盖率 | Top-3 达标 | 中心误差中位数 | 锚框 / 池内 Oracle mIoU | Bind 中位耗时 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 开发 | A | 78.2% / 71.3% | 339 / 566 | 0.392 m | 34.31% / 40.86% | 1.12 ms |
| 开发 | B | 88.0% / 43.9% | 182 / 566 | 0.427 m | 32.42% / 40.13% | 8.11 ms |
| 开发 | C | 85.7% / 60.6% | 322 / 566 | 0.369 m | 34.31% / 42.08% | 10.69 ms |
| Mono | A | 74.9% / 62.9% | 65 / 132 | 0.334 m | 38.99% / 46.36% | 1.38 ms |
| Mono | B | 80.5% / 39.7% | 30 / 132 | 0.382 m | 32.06% / 41.83% | 14.92 ms |
| Mono | C | 77.8% / 46.7% | 54 / 132 | 0.344 m | 34.44% / 43.52% | 19.62 ms |

Bind 计时包含分组、回波关联和排序，比较三个版本都调用 Bind 的 556 条开发查询与 101 条 Mono 查询。Intel Core i5-14600KF 单线程下轮换执行顺序，计时区间排除读取、公共地面拟合、Qwen 与核验器。Oracle 使用 GT 从候选池离线挑选最高 IoU，只用于诊断。

- **A** 在开发面板提高了覆盖率，锚框 mIoU 与 C 持平，但候选池平均由 10.10 个收窄到 8.18 个，Oracle mIoU 由 42.08% 降到 40.86%。Mono 上 A 的锚框和 Oracle 同时改善，说明仅用窗内深度就能在这一面板生成更好的候选。两个面板的差异不足以支持部署时切换规则。
- **B** 在两个面板都提高了支持点纯度，但覆盖率、Top-3 达标数和中心精度下降。结果与单阈值把物体支持切碎的解释一致，同时也受回波关联半径影响。本轮未单独拆开这两个因素。
- 论文将 Bind 表述为无学习参数的点云实例绑定。在冻结的 S5-pass 下，四尺度在开发面板保留了更多可用几何假设。结果适用于本轮固定阈值，以及基于原四尺度候选训练和标定的 Verifier。

## 复现

以下命令从已恢复的工作区仓库根目录运行，使用 Python 3.12 和 RTX 5090。完整回放依赖此前的本地历史研究脚本、S5-pass checkpoint、两份冻结缓存及 LiDAR 数据。GitHub 分支提供本轮实验代码、聚合结果和方法说明，完整复跑仍需这些工作区资产。

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
../.venv/bin/python -u studies/3eed_adaptive_bind_20261128/run_adaptive_bind.py predict
../.venv/bin/python -u studies/3eed_adaptive_bind_20261128/run_adaptive_bind.py score
```
