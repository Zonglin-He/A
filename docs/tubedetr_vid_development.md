## 顺序、参数与决策

必须等原两方向主表及五行消融都有完整final seal、全部引用文件哈希正确且原两个控制进程正常结束，才开始任何参数候选评价。等待阶段没有新GPU工作，状态与原运行独立。

1. 初始化：gamma∈{0,0.05,0.1,0.25,0.5,0.75,1}的精确初始化读出，只在128评分。gamma0是时间分支控制，不冒充完整方法。先选非零gamma的初始化最优值。
2. 学习率：固定上述gamma、tau0.5、30步，比较0.0025/0.005/0.01/0.02，同时保留原Full基线。原OPD效应很小不等于LR过大，必须同时测试减小与增大。
3. 温度：在当前128完整定位最优配置上比较0.25/0.5/1。保存实际候选权重熵、有效样本数ESS、状态梯度范数和伪标签损失。高熵优先测试较低温度，但保留两方向对照；不能把伪损失下降当作定位收益。
4. 更新步数：比较15/30/60。一次60步保存15/30前缀；已有独立30步输出必须逐位等于60步中的30前缀。观察定位是否随伪损失下降而下降，区分更新不足与对错误伪标签的过拟合。
5. 耦合复查：在当前优化参数下只试相邻非零gamma，最多两个新配置。

每阶段保存所有候选、正负结果、实际选择和下一步理由；每query仍使用相同输入key/seed41，不做GT选例、GT门控或query独立选参。选择目标是全128等权query的Full m_vIoU最大值，原配置始终是候选；严格相同结果优先保留原配置，再优先较少步数。最多9×128条新开发fit路径及最多5次原配置回放资格检查，有限预算不自动扩展。时间Strong、校准、policy尺度、alpha1、单专家、冻结网络和每query重置不变。

## 缓存、检查与全量

每批128中一次224原生编码供该条query的多个候选复用；每条query第一次仅调用一个ReferDINO，伪框与原封存专家证据hash必须一致，后续批次复用该八帧证据。重新编码的Source框与Native区间须与原全量逐位一致，gamma1原初始化亦须一致；每个worker第一次参数拟合前还要复现原默认OPD输出，失败按接口/工程问题停止。模型完整状态hash批次前后相同，每个候选新建临时状态及优化器并清零。

128选参结束后先锁selected_profile，才运行所选全局配置的10303条全量，并保留新的五行结果。空间参数不改变Strong，可精确复用原Strong/Native区间；选中配置的128预测在相同输入、seed、权重、证据和配置下复用到全量。其余query重新进行真实空间适应，不能线性变换旧Live冒充新LR/温度结果。若原配置仍最优，则旧全量精确复用，不制造重复GPU成本。全量结果出来后不再反向调参。

原主表/消融/效率完整保留。新执行含Strong缓存及128缓存，不能把其耗时称作全新端到端部署效率；原主实验的实际效率仍有效，调参计算成本另记。完整新结果、父来源平均、聚类统计、负例和曝光披露单独存于results/tubedetr_vid_development。
