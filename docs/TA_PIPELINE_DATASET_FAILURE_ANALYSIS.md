# 正确预测沿 pipeline 的损失，以及 VidSTG / HC-STVG-v2 数据特点

2026-10-04。按用户请求回读封存最佳 quick 的全链条、deep GT 标量和后续 oracle/teacher 实验，并以 CPU 核对同批输入网格与已经曝光的 annotation 时间元数据。本次新增模型 forward、expert call、参数更新、GPU 初始化、box GT 评分均为 0。未恢复全 query 队列、未改方法、未重新选参数；GT 分组仅为事后解释。

**结论：Vid 的有效空间继承与局部执行损害同时存在；时间 Fast 是严重单样本负尾的重要入口。HC 的主要全流损失在空间状态继承，正负迁移几乎抵消；时间 Fast 又会破坏一部分刚达到较高定位质量的输出。数据集差异能解释观察覆盖与语义接口的风险，但没有把任一阶段唯一归因于数据集、K8、切镜头或专家能力。**

## 1. 用什么设置回答这个问题

完整损失账以已公开的 `tastvg_best_quick_v1` 为准：Vid 670来源/一query/两序/clean+五类5%瞬态corruption，共8040到达；HC-v2 128来源/一query/一序/六条件，共768到达。corruption分别6700/640。25%专家，各自官方同域TA-STVG checkpoint，224px、原Paper48采样、1792空间参数；Vid K1/lr .033761698432507946/teacher .34902548789596055，HC K8/lr .006097133675874025/teacher1，rho .05/student1/D4。

来源全部历史曝光。每源一条query不是官方全query benchmark，HC只一序不能用来建立顺序稳定性。当前生产注册仍由 `methods/CURRENT_METHOD.json` 决定；研究A未被本分析晋升。

正式时序是：Frozen参考 → 到达前继承空间状态 → 时间Fast读出 → 当前输出封存 → 当前空间SGD写入，供未来query使用。当前更新后输出只作fixed-time诊断，不是正式online当前输出。空间/时间中间读出是指标记账，不能冒充独立神经模块干预。

主结果：Vid corruption source-macro dense vIoU +1.3468pp，来源配对10000 bootstrap CI[.9485,1.7582]；HC+.2134[-1.0299,1.4268]。Vid已建立正收益，HC未建立稳定净收益。旧默认J01/SGD.005/K1的CPU报告与本配置不同，不混用其破坏计数或“时间损害5.47倍”结论。

## 2. 原本正确的样本究竟在哪一步丢失

正确定义为严格 dense joint vIoU>.3 或 >.5；表中分母是该阶段之前正确的到达，不是全部query。

| corruption阶段 | 净ΔvIoU pp | gross gain / gross loss pp | >.3正确→错 | >.5正确→错 |
|---|---:|---:|---:|---:|
| Vid 空间状态继承 | +1.2481 | 1.8825 / .6344 | 71/2046，3.47% | 58/1012，5.73% |
| Vid 当前时间Fast | +.0987 | .6291 / .5304 | 57/2197，2.59% | 33/1137，2.90% |
| HC 空间状态继承 | +.0166 | 1.2886 / 1.2720 | 10/270，3.70% | 4/78，5.13% |
| HC 当前时间Fast | +.1968 | .5560 / .3592 | 0/279 | 8/102，7.84% |

继承时间项在该保存面板逐条为0。空间会先纠正一些原本错误的预测，Fast也可能破坏这些新纠正的预测，所以71+57不能当作Vid最终正确损失。

把Frozen正确、最终错误的记录逐条沿链追踪，得到互斥路径：

| 数据集、阈值 | 最终丢失Frozen正确 | 先在空间继承后失去正确性、最终仍错 | 空间之后仍正确、再被Fast改错 |
|---|---:|---:|---:|
| Vid >.3 | 116/2046 | 69 | 47 |
| Vid >.5 | 78/1012 | 58 | 20 |
| HC >.3 | 10/270 | 10 | 0 |
| HC >.5 | 6/78 | 4 | 2 |

这是一条输出阈值路径的完整记账，不等于已识别某次历史write的因果。HC Fast的8次>.5破坏中，2次来自Frozen已正确且空间保留的输出，另6次破坏了空间刚纠正到>.5的输出。

Fast只在专家到达调用；全流表稀释了调用时风险。真正专家到达中，Vid>.3为57/531=10.73%，>.5为33/291=11.34%；HC>.3为0/69，>.5为8/23=34.78%。重复condition/order相关，HC严格阈值损害涉及3个独立来源，不能把8次当8个独立视频。

严重负尾又是另一种排序：Vid空间继承>5pp损害207次/74源、>20pp23次/9源；Fast分别206次/61源、47次/14源。HC空间为39/10、6/2，Fast16/5、0/0。**Vid最严重的单次灾难更多从Fast进入；HC的>20pp尾部来自继承空间，集中在2源的重复条件。** 阶段尾部也不能相加为最终尾部。

## 3. 时间端：既有正确候选漏选，也有当前支持无法给出正确joint输出

| corruption专家位置 | 正确候选至少一条 | 正确候选存在但漏选 | 没有正确joint候选 |
|---|---:|---:|---:|
| Vid >.3，1680位置 | 698 | 159/698，22.78% | 982 |
| Vid >.5 | 403 | 104/403，25.81% | 1277 |
| HC >.3，160位置 | 77 | 4/77，5.19% | 83 |
| HC >.5 | 35 | 14/35，40.00% | 125 |

这些候选固定当时继承空间框；“所有joint候选不正确”不能全算时间生成错误。已有tIoU>.5时间候选而仍无vIoU>.3候选的记录，Vid311/1680、HC38/160，说明空间质量仍可能挡住joint成功。

Fast为 `max_m confidence_m * interval_IoU(candidate, proposal_m)`。它奖励与高confidence proposal匹配，并未学习该STVG查询的定位IoU。Vid>.3的57次破坏中50次同时存在好teacher proposal、实际胜出贡献teacher却差，>.5为20/33；HC>.5为3/8。匿名Vid source63/occlusion/order2：空间仍为v=.55562，候选oracle=.61212，Fast选完=.01820；最佳teacher t=.87352，实际贡献teacher t=.02607。正确支持没有被可靠转为修改许可。

后续小面板的oracle已分开了可表达时间网格、少量候选覆盖、候选内选择：Expanded32保留Old8后增加oracle机会，但原UVTG argmax实际变差；PE语义均值与同曲线边界transition也未建立可靠收益。DTA R1说明正确teacher可通过514参数head梯度改善定位，R2错中心会被成功学进去，R2b raw等权mass也失败。这些是teacher构造/选择问题的佐证；不是与本表可相加的新“正确损失计数”。

## 4. 空间端：参考证据、偏好编码、梯度执行、未来继承必须分开

corruption专家参考为空Vid211/1680、HC20/160；非空但没有GT计分事件内参考Vid400/1469=27.23%、HC15/140=10.71%。有事件内有效框的到达，参考GT-IoU中位数约.726/.723，不能概括为Sa2VA总是不会定位。

九个候选的reward比较全clip Uniform5有效框；student的geometry-softmax比较全采样tube。任务却只在查询成立的GT事件内计分。专家观察、loss支持与任务支持并不相同。事件外参考仍可能帮助对象几何，不能把400次全算坏监督，也不能拿GT支持线上过滤。

专家reward第一二名差中位数约.0018，却经rank+温度变成q_top约.943（Vid）/.632（HC）。该q不是专家正确概率；几何student p也不是native tube生成概率。flat reward仍可能产生熵梯度，但后续近端目标/位移约束消融没有确立双数据集改善，不能重新把它们写成已验证修复。

更直接的执行反例是：专家唯一首选候选优于当前tube，更新后fixed-time vIoU反而下降，Vid159次、HC11次。Vid source70/occlusion/order2：当前v=.44727，唯一首选=.46489，SGD后=.21614，KL反而从9.40289降到8.92701。这里失败发生在偏好到参数执行，不能归为没有好候选或时间选帧错。正例source240/drop/order1则从.19262升到.37467；Vid正式空间继承净+1.2481pp，成功路线仍需保留。

HC当前K8的每一步以及最终固定时间净更新都没有>5pp单次损害，完整当前更新净值+.0465pp CI跨0；而正式继承空间gross gain/loss为1.2886/1.2720。两者并不矛盾：当前输入上的小更新效用不保证将同一共享状态用于下一视频仍有益。尚未隔离每次历史write的未来因果，也没有单调长流崩溃证据；不能直接把HC失败命名为K8过大或灾难性遗忘。

后续确认小面板GT-space理想替换增量Vid+23.65pp、HC+32.49pp，九个空间probe oracle却只有约+.40/+.75pp（原A时间）。这是当前局部候选覆盖很窄的证据，不限制其他表征或更新机制的上限。GT-space和GT-time条件上限不能加总为独立贡献。

## 5. 数据特点如何对应上述损失

原始VidSTG由VidOR关系标注构建，查询包括目标外观、对象关系和环境；疑问句刻意省略被问目标的外观。目标是在untrimmed输入中定位查询描述成立的时段，而非跟踪所有目标可见帧。[VidSTG原论文/补充](https://arxiv.org/pdf/2001.06891)、[官方schema](https://github.com/Guaranteer/VidSTG-Dataset)。

HC-v2是电影场景中的特定人、动作及人与人/物关系描述，输入20秒，事件外扩展部分承担时间负样本作用。人仍可见不表示描述的动作仍成立；其他人的属性与场景context可以帮助消歧。[HC官方仓库](https://github.com/tzhhhh123/HC-STVG)、[HC原论文](https://arxiv.org/pdf/2011.05049)。v1原论文禁止已标注事件内切镜头；不能因电影来源就认定当前损害由切镜头导致。v1均值/多人统计不直接冒充本批v2分布。

本次直接复算同批quick元数据，避免用官方全体平均值替代当前样本：

| 当前quick来源统计 | Vid670 | HC-v2128 |
|---|---:|---:|
| 已采样首尾包络观察窗中位数 | 17.83s | 19.96s |
| 标注事件时长中位数 | 3.82s | 6.16s |
| scorer事件跨度/观察包络中位数 | 27.37% | 30.66% |
| 事件跨度≤观察包络25%的来源 | 314/670 | 43/128 |
| Uniform5五个位置均不在GT标注事件内 | 175/670，26.12% | 13/128，10.16% |
| 选取的query类型 | 315陈述/355疑问 | 128陈述 |

观察包络不是原视频文件时长，也不完全等于官方used_segment长度；Vid实际采样15–200帧、中位90，HC每条65帧，不写成统一64帧。Vid原视频/官方used_segment/已采样包络均值分别37.0205/25.9672/25.8274s。HC annotation event计入最后一框，既有scorer采用最后一框作为exclusive span end，因此报告两种时长：annotation中位6.16s/scorer6.12s。Vid146条scorer事件略超已采样包络，但超出真实官方used_segment为0；这是保留网格首尾覆盖差，不是146个事件被原输入clip截断。未观察事件比例全体均值.4433%、中位0、最大28.57%；未裁GT来掩盖它，比例可能>1。该尾部值得保留，但不能把它宣称为主损害原因。

**事件短、观察稀疏的关联已具体出现。** Vid400次非空无事件内参考中，370次来自≤25%组，占92.5%；该组617次非空参考中370次不覆盖事件。几何五位置零命中在corruption专家位置为485/1680（与400不同：还包括空mask），HC为10/160。每个condition/order复用来源，不是独立视频计数。

Vid≤25%组中，Fast把原本>.3正确的专家到达改错32/100=32.0%；>.50%组17/356=4.78%。对应全流Fast净值−.0688/+ .2072pp。短事件组Frozen本身也更难（9.94% vs35.74%平均vIoU），所以此处是风险共变，不是已调整因果，更不是筛短事件的线上建议。HC短组>.5只有3次前正确到达，2次受损；分母太小，不建立HC同一普遍规律。

400次无事件内参考还可分解：352次的五个位置几何上就无事件帧，48次几何上存在事件帧但有效mask全部在事件外。这两类不能混为一个观察失败。HC15次对应5/10。几何零命中并不证明非空框跟错身份：事件外同一个人可能仍可见，只是此GT不支持评测。若改用官方used_segment分母，仅3条Vid移到相邻比例组，370/400结论不变；原分组保留，未按GT切换主口径。

上述专家条件损害率以cells为分母，未宣称独立source置信区间。Vid专家292源中248源各有5个corrupt专家cells、44源各10个；专家cell均值不能冒充等源均值。全流每源10个Vid/5个HC cells，来源等权与全流cell均值才相同。

**疑问句存在具体语义接口风险。** Vid question空参考155/890=17.42%，caption56/790=7.09%；Fast>.3破坏38/229=16.59% vs19/302=6.29%，>.5为24/142=16.90% vs9/149=6.04%。本地expert worker明确关闭query unifier；疑问句不带被问目标外观，而UniversalVTG没有目标person box输入。缺少referent/关系消歧可能导致“相关动作”与“这个目标的这个事件”混淆，但query类型与事件长度、目标类别等未做匹配控制。question组空间净增益反而+1.4756pp，高于caption+.9916pp，不能说疑问句一律无用或方法只适用陈述句。[UVTG官方decode](https://github.com/jbistanbul/universalvtg/blob/master/universal_vtg_inference.py#L821-L849)的confidence是分类logit sigmoid、边界offset另回归，不是针对STVG定位质量的保证。

**HC不是简单的“没有时间错配”，而是现有困难权重不同。** 它的Uniform5事件零命中更少，但空间净迁移仍几乎抵消，故命中事件不是充分条件。人类目标单一类别不意味着多人身份与动作关系更易区分；参数共享跨不同视频，身份/关系特定纠正不一定能迁移。HC较大GT-space headroom和较小九probe上限也提醒，已有框/候选表达仍不足。最新P0 A-ROI teacher确认HC+13.927pp CI跨0，3好4坏、前2源占gross positive83.12%；crop改变尺度、背景、关系context和运动，不能用这个局部均值把HC问题唯一归为身份或背景。

条件分层同样不能凭展示案例代替全体：Vid五类空间与Fast净均值均正，空间drop/blur gross loss较大，occlusion空间净+1.6786pp反而最强。HC Fast的freeze/occlusion均值−.0873/−.1750pp，贡献>.5破坏5/8；空间gross loss五类都在1.09–1.36pp，不只限于这两类。这是描述性分层，没有新增条件置信区间或显著性声明。

## 6. 判断边界与当前决策

损失链至少包括：事件/身份条件与观察支持错配 → teacher局部排序与尖锐偏好编码 → 偏好不能安全兑现为参数执行 → 跨视频继承抵消 → 时间支持与teacher选择破坏当前正确输出。它们存在关联，但没有被一个唯一因果机制解释。

按正确样本数量，优先保留并审查空间状态继承路径；按Vid灾难性单次负尾与HC高阈值调用风险，时间teacher的修改许可必须单独审查。保留已成立的Vid空间收益；HC不以小正均值宣布成功。当前分析不恢复旧readout/calibration搜索、不调K/LR、不添加gate、新expert或新loss，不把GT分组写成方法规则。

新增可复算材料为 `results/tastvg_pipeline_dataset_analysis/2026-10-04` 的匿名元数据、SUMMARY与公开标量审计；分析脚本不解码媒体、不加载权重、不重算box指标。完整成功/失败例参见 [最佳quick](TA_BEST_QUICK_REVIEW.md)、[deep GT分析](TA_QUICK_DEEP_GT_ANALYSIS.md)、[oracle](TA_ORACLE_EVENT5_REVIEW.md)、[最新P0](TA_SPATIALLY_GUIDED_TEMPORAL_P0_REVIEW.md)。所有新分组均为事后描述，来源相关、不同优化设置与checkpoint均是混杂；不把这些结果称为全量、新鲜测试或已识别数据集因果。
