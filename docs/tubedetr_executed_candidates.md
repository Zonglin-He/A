# TubeDETR：执行后的候选是否提供Direct局部方向之外的价值

## 动机与不预设的结论

完整mask资格的两个信号都未通过：MaskDice成对排序74.473%、top1 regret0.147697；MaskContrast61.645%、0.231499；几何74.995%、0.121997。mask更细并不意味着更适合矩形轨迹定位，替代query竞争也可能损害正确目标。不得据此运行其适应或全量。原生文本分数对事件支持AUC0.6512只在81条同时观察到事件内外位置的query可计算，无法覆盖26条完全错过事件的情形。

用户要求思考“为什么”：局部平滑奖励下，OPD方向近似Direct梯度；逐帧自匹配仍偏向复制教师；原输出框候选不是真实decoder执行轨迹。新探针只检验最后一个可证伪问题：在相同有限真实forward次数下，OPD随机方向是否比Direct方向的充分线搜索提供更好的、能够由同一奖励选出的轨迹？不能预先保证存在这种优势，也不能把GT oracle当可部署选择器。

## 固定面板与候选

沿用原输入哈希16条，不按已知负例换query。只加载原冻结TubeDETR，复用原单ReferDINO八帧特征，无新专家调用。各query从相同零content/初始化出发，计算原Layout3奖励Direct梯度、原混合密度OPD seed41/42/43/44的梯度；由原lr0.02/Adam首步构成状态方向。

- Direct方向搜索：首步方向乘固定系数±(1/32,1/16,1/8,1/4,1/2,1,2,4)，另含零状态，共17个实际decoder执行。
- OPD方向搜索：4个随机种子方向各乘−4/−1/1/4，另含零，共17个实际执行。
- 相同最大状态尺度与forward次数；OPD多3次backward，必须披露，不能称等算力公平比较。Direct有更细的步长覆盖，不故意限制它。
- 两组均按**实际执行后**的同一八帧平均Layout3奖励选择；分数并列时优先状态范数最小。GT不参与选择。Direct与OPD41的系数1候选须逐位复现此前真实单步探针，确保接口一致。

这些是“由OPD/Direct梯度构造的候选搜索探针”，不是原OPD的60步方法，不能把其16条差值写进主表。最多16×34次真实候选forward、无多步fit、无参数选择、无新全量。完整候选seal后独立CPU读取GT，按原DenseTube与Strong时间评分。

## 分析与后续约束

报告奖励选择后的实际定位、配对父区间、零状态被选次数、局部一阶预测为负但有限执行奖励为正的query数；另外报告GT oracle候选上界，明确oracle不可部署、不代表算法成绩。若oracle较好但同奖励选择不能改善，说明主要瓶颈仍是奖励辨别力；若OPD随机方向不胜Direct线搜索，不声称当前设置已有候选级优势。

此阶段后主线程据结果决定是否值得构造事件支持/身份竞争/执行后影响的结构化评价。不能仅为了让Direct不可微而制造硬选择，也不重复盲试局部相似度。旧HC/空间数值队列继续暂缓。控制器/worker/score独立，GPU尊重runtime/gpu.lock，代码和计划事前绑定、先完整seal后离线评分、不自动重试。
