# Fixed single-view temporal budget trial

This is an explicitly authorized TA-STVG development screen and two-direction
DEVELOPMENT RECHECK. The paused full evaluation, all its frozen sources and
production Strong configuration stay unchanged. No OPD/training/new teacher.

The only new candidate is native full-frame height320, original offset0, native
two-pass temporal inference. Its normalized interval posterior is independently
drawn twice through the original hull operator, scattered to the unchanged full
physical frame grid, then fused .5/.5 with original224 two-offset Global6. Original
physical MBR and full native-box BoxFixed are retained. No288/352/384 sweep,
weight/temperature tuning, query-wise offset selection or new internal-head score.

HC63 uses the same already exposed63 as the completed448 decomposition. New320
predictions seal before locked-label CPU scoring. Source, Global6, original Strong,
and both fixed448 offset self-hull references reuse verified outputs. Fixed same
spatial tracks isolate temporal effects; actual final DP is separately scored.

The prespecified engineering screen requires all: complete vIoU loss <=1pp versus
Strong; positive tIoU AND full vIoU versus Global6; >=40% reduction of the additional
temporal branch wall versus original dual448. These are point-estimate engineering
preferences, not statistical equivalence. If it fails, end320 without scanning;
the separately authorized44832x2 recheck still proceeds.

Eight fixed HC63 queries compare real320single0,448single0 and448dual in rotated
order on the same resident model. Required preprocessing, CPU/GPU transfers,
native temporal execution and posterior/MBR are included; no per-module timing
synchronizations. This is additional-branch timing, not complete-method latency.

HC32 and Vid32 reuse the existing parent/video-separated fixed selection. These
panels were previously used for development; they are not unseen confirmations.
Both448 offsets remain separately fixed, with offset0 primary and offset1
sensitivity.320 joins only if the HC63 gate passes. All64 new predictions seal
before new independent scoring.

For actual end-to-end timing, four fixed queries/domain (indices0,10,21,31) run
EACH complete method independently, including raw RGB decode,224 both offsets,
actual eight-frame ReferDINO, ERef/evidence/complete-box geometry, the actual extra
views, transfers, posteriors/MBR and final DP. No cached evidence or discarded-view
cost is substituted. Native weights and teacher are resident across runs; their
load/start costs and the first query are separately visible. Arm order rotates;
whole-query and excluding-first means plus individual timings are published.
Only eight queries support these complete latency measurements, not all64.
The remaining precision runs reuse common224/spatial captures and are never
claimed as end-to-end timings. Every timed pipeline must reproduce its precision
prediction bitwise; original Source/Global6 must recover the old32 references.

Implementation: `scripts/singleview_budget/{model,run,score,capture,recheck,recheck_score}.py`.
All public results include signed losses, severity >5pp, tIoU threshold crossings,
observed/unobserved spatial metrics, boundary errors/length and paired parent CIs.
No query text, GT coordinates, videos, tensors, weights or raw evidence are public.

## HC63 screen outcome

The fixed320 candidate failed: full vIoU29.7743%,tIoU55.3051%, versus
Global630.0946%/56.2981% and Strong31.8466%/59.1483%. Full-v loss versus

cost criterion passes (1.8733s versus3.5134s,46.68% lower), so speed alone does not
justify adoption. End320 without any32-domain trial or adjacent-resolution scan.
